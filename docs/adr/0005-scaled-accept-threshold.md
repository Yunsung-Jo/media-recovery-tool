# 0005. resync 수락 임계를 잔여 비례(0.35W)로 스케일하고 데이터-끝 완주 run을 수락

- **날짜:** 2026-07-03
- **상태:** Accepted

---

## 배경

재동기(resync-skip)와 바이트 편집의 수락 임계는 절대값이었다 — 재동기
`run ≥ max(250, maxW//2)` = 450 MCU, 편집 `run > 120`. probe 창(maxW=900)도 고정이라,
**총 MCU < 450인 소형 이미지는 재동기 수락이 산술적으로 불가능**했고, 일반형으로는
**연속 손상 간격 < 450**이면(총 MCU가 커도) 어떤 재개 후보도 수락되지 않아 첫 디싱크
이후 전량 회색으로 남았다. W1 베이스라인(822건) 기준 FAILED 66건(undec_after 합 33.58)의
주원인이다. 실증: [사각지대 조사](../investigations/2026-07-02-recovery-tool-blindspots.md)
2~4단계(스케일 임계로 잠금 5건 중 4건 복구), [blocky 조사](../investigations/2026-07-02-blocky-shift-dc-offset.md)
4단계(간격<450 일반형 규명).

임계를 낮추면 masking(어긋난 스트림을 그럴듯하게 수락하는 가짜 복구) 위험이 커진다는
우려가 있었고, 백로그 W2는 DC 물리 범위 불변량(dequant DC ∈ [−1024, +1016]+q0/2 —
[레퍼런스 §디싱크 판별의 불변량](../reference/jpeg-entropy-coding.md)) 채점을 안전장치로
전제했다. 이 전제는 실험에서 기각됐다(아래 대안 표).

## 결정

각 디싱크 지점 m_d에서 잔여 `rem = 총MCU − m_d`, probe 창 `W = min(900, rem)`으로:

| 항목 | 종전 | 변경 |
|------|------|------|
| 재동기 수락 | `run ≥ max(250, maxW//2)` (=450) | `run ≥ max(30, 0.35·W)` **또는** `stop=버퍼끝 & run ≥ 30` |
| 편집 수락 | `run > 120` | `run > min(120, max(20, 0.4·rem))` |
| 편집 개선폭 | `base + 30` | `base + min(30, rem//4)` |
| masking 가드 | `\|db\| ≥ 24` | 유지 |

근거:

- **0.35 계수**: 표본에서 진짜 재개점으로 확정된 한계 후보들의 run/W 비가 0.37~0.47
  (0xCE2DF000 167/448=0.37, 0xC8069000 105/254=0.41, 0xC9CD0000 294/631=0.47)이라 이들을
  모두 수락하는 값. 선행 실증(4/5 복구)의 0.55는 이 셋을 놓친다. 한계 후보 3건 전부를
  세그먼트 수동 구성 직접 렌더로 검증한 결과 **실제 콘텐츠**였다(조사 5단계) — 표본에서
  "손상 지점의 best-run 후보가 garbage였던 사례"는 0건이므로 더 보수적일 이유가 없었다.
- **바닥 30**: 그보다 짧은 run은 진위를 검증할 신호가 없다(조밀 코드 공간에서 임의
  정렬도 수십 MCU는 유효 디코드됨).
- **데이터-끝 완주 규칙**: probe가 버퍼 끝에서 멈춘(stop=3) 후보는 남은 데이터 전체가
  이어진다는 뜻이고, 데이터가 소진돼 **그 뒤에 가릴 내용 자체가 없으므로 masking이
  구조적으로 불가능**하다. 절단 파일(EOI 부재군)에서 남은 데이터가 창 비례 임계에 못
  미칠 때 이 규칙이 절단 앞 콘텐츠를 살린다(0xC9CD0000 undec 0.988→0.523).
- **편집 임계 스케일**: 소형·꼬리 구간에서 절대 임계(120)가 같은 방식으로 수락을 막는다
  (예: 0xC7FEE000 — 스케일 후 sub 1 수락으로 undec 0.195→0.000 완전 복구).

전수 822건 검증(`--time-budget 0`): FAILED 66→15(RECOVERED 전환 51), **파일별
undec_after 악화(+0.01 초과) 0건**, RECOVERED+FAILED undec 합 47.38→24.05, MCU 대역
120–449 평균 0.121→0.018. 전환 표본 12건 육안 masking 0건. 과정 전체는
[W2 조사 기록](../investigations/2026-07-03-w2-scaled-accept-dc-scoring.md).

## 대안

| 대안 | 기각 이유 |
|------|----------|
| DC 물리 범위(±1016+q0/2) 위반 비율로 후보 기각 | **정당하게 수락되는 후보가 위반을 일상적으로 보유** — DC=0 리셋 오프셋·불완전 편집 잔존 오차 탓에 가드 수락 세그먼트의 위반 비율 최대 0.88(조사 2단계). 필터로 쓰면 기존 복구를 대량 오기각 |
| per-comp DC 스팬(max−min ≤ 2040+q0, 오프셋 무관) 기각 | 무편집 probe 창조차 plausibility 경계(±1400) 안의 잔존 드리프트를 포함 — 정당 수락 후보 52건 중 31건이 스팬 한계 초과(실증 복구 0xC8BC4000 스팬 2370 포함). good(2370~2723)과 suspect(2620)가 겹쳐 판별 불가(조사 4단계) |
| 같은 비트 DC 후보(carry/zero) 동률을 물리 위반 최소로 선택(tie-break) | 수락 집합 불변이라 안전하고 클리핑 축소는 실측(viol 55→1)이나, 육안 이득 불명확 + 전수 diff 소음 — W5(색 보정)와 결합 재평가로 백로그 이관(조사 7단계) |
| maxW 자체를 줄여 절대 임계 유지 | 수락 바닥 250이 지배해 소형에서 여전히 잠금 — 선행 조사에서 기각([사각지대 조사] 4단계 주의 항목) |
| 0.55·W (선행 실증값) 유지 | 진짜 재개점 3건(run/W 0.37~0.47)을 놓침 — 직접 렌더로 콘텐츠임이 확인된 후보를 임계만으로 버리게 됨 |

## 결과

**실제 영향**

- `carver/resync.py`: `recover()`가 probe 창을 잔여로 캡하고, `_resync_skip()` 수락식이
  창 비례 + 데이터-끝 규칙으로 변경. `_probe_stop()`(정지 사유 반환) 추가.
- 전수 822건: RECOVERED 487→539 / FAILED 66→15 / CLEAN 143→142(1건은 RECOVERED로
  이동하며 완전 복구) / SKIP 126 불변. 전수 실행 17.6분(-j 12, `--time-budget 0`).
- 잔여 FAILED 15건 = 헤더 손상·초소형 11(백로그 W3 대상) + 사실상 정상 1 + 절단·데이터
  한계 3.

**감수한 트레이드오프**

- run 30~150의 저임계 수락은 450 시절보다 검증 신호가 약하다. 표본·전수 육안에서
  masking 0건이었으나, **저엔트로피(EOB 지배) 구간에서 clean run의 정렬 판별력이 0**이라는
  기지 한계는 그대로다 — 짧은 수락 세그먼트의 정렬 오류 가능성은 남는다(밀림·캐스트
  보정 W4·W5에서 다뤄질 결함 유형).
- 수락 세그먼트 수 증가로 세그먼트별 색 캐스트·밀림 결함의 총량은 늘 수 있다(회색보다
  콘텐츠+결함이 낫다는 판단 — W4·W5의 입력이 된다).

**향후 고려사항**

- **DC 물리 범위 불변량을 수락/기각 필터로 재도입하지 말 것** — 복구 출력과 probe 창은
  물리 불변량을 이미 위반한다(위 대안 표). 유효 용법은 같은 비트 DC 후보 동률
  선택(백로그, W5 결합)과 진단·분석 신호에 한정된다. 백로그 W6(단편화 probe)의 "물리
  채점기 재사용" 전제도 같은 이유로 재검토가 필요하다.
- 0.35 계수는 표본(진짜 재개점 run/W 하한 0.37) 기반이다 — 새 코퍼스에서 masking
  수락이 관찰되면 이 계수보다 먼저 **파일별 undec 회귀 diff + 저임계 수락 표본 육안**
  절차(이번 검증 방식)로 원인을 가른 뒤 조정한다.
