# 0005. resync 수락 임계를 남은 MCU에 비례시킨다

- **날짜:** 2026-07-03
- **상태:** Accepted

## 배경

기존 재동기 수락 기준은 `run >= 450 MCU`, 바이트 편집 기준은 `run > 120 MCU`인 절대값이었다.
이 때문에 전체 MCU가 450보다 작거나 다음 손상까지의 간격이 450보다 짧은 파일은 올바른 재개점을
찾아도 수락할 수 없었다. 단순히 임계를 낮추면 잘못 정렬된 스트림을 진짜로 오인하는 masking 위험이
커지므로, 남은 데이터 양에 맞춰 검증 창과 임계를 함께 줄일 기준이 필요했다.

## 결정

디싱크 MCU를 `m_d`, 남은 MCU를 `rem = total - m_d`, probe 창을 `W = min(900, rem)`으로 두고 다음
규칙을 사용한다.

| 항목 | 수락 조건 |
|---|---|
| 재동기 | `run >= max(30, 0.35·W)` |
| 버퍼 끝까지 이어진 재동기 | `run >= 30` |
| 바이트 편집 | `run > base + min(30, rem//4)`이고 `run > min(120, max(20, 0.4·rem))` |
| masking 가드 | 원래 위치와 24비트 미만 떨어진 재개점 거부 |

0.35는 실제 콘텐츠로 확인한 한계 후보들의 `run/W` 최솟값 0.37보다 약간 낮은 값이다. 30 MCU보다
짧은 run은 조밀한 Huffman 코드 공간에서 우연한 정렬과 구분할 신호가 부족해 바닥으로 둔다. 버퍼
끝에서 멈춘 후보는 뒤에 가릴 데이터가 없으므로 같은 30 MCU 바닥만 적용한다.

## 대안

| 대안 | 기각 이유 |
|---|---|
| dequant DC 물리 범위로 후보 기각 | DC=0 재개 오프셋과 잔존 드리프트 때문에 정당 후보도 범위를 자주 위반한다. 기존 복구를 오기각했다. |
| DC 스팬으로 후보 기각 | 정상 후보와 의심 후보의 분포가 겹쳐 판별력이 없었다. |
| probe 창만 줄이고 절대 임계 유지 | 250 MCU 절대 바닥이 남아 소형 파일 잠금을 풀지 못한다. |
| `0.55·W` 사용 | 실제 콘텐츠로 확인한 `run/W=0.37~0.47` 후보를 놓친다. |

## 결과

소형 이미지와 짧은 손상 간격에서도 재동기가 가능해졌다. 당시 전체 데이터 검증에서는 FAILED가
66개에서 15개로 줄었고 파일별 `undec_after` 악화가 없었다. 이 수치는 결정 당시 효과를 나타내며,
현재 기준선은 [현재 상태](../current-state.md)를 따른다.

낮은 임계로 수락되는 세그먼트는 이전보다 검증 신호가 약하다. 특히 저엔트로피 구간에서는 clean run의
정렬 판별력이 낮고, 수락 세그먼트 증가로 밀림·색 캐스트가 늘 수 있다. 회색으로 버리는 것보다 복구한
콘텐츠를 남기는 쪽을 선택한 결과다.

DC 물리 범위는 진단이나 동일 위치 후보의 보조 비교에는 쓸 수 있지만 수락·기각 필터로 재도입하지 않는다.
