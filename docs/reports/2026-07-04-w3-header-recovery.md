# 보고서 — 헤더 복구 pass: 열지 못하던 사진 55장을 되살림, 손상 없던 사진 회귀 0

- **날짜:** 2026-07-04
- **대상/범위:** 추출된 손상 JPEG 822장의 복구 결과 — 헤더 복구 pass 적용 전(W2) vs 적용 후(W3), 동일 표본·동일 조건(`--time-budget 0`)
- **한 줄 요약:** 파일 앞부분(헤더)이 깨져 **아예 열리지 않던** 사진 61장을 되살렸고(그중 45장은 사실상 완전 복구), 이미 잘 복구되던 사진은 **한 장도 나빠지지 않았다.**
- **관련 문서:** [ADR 0006](../adr/0006-header-recovery-structural-gates.md)(설계 결정)·[recover 스펙](../specs/0002-recover.md)(동작)·[W3 조사 기록](../investigations/2026-07-04-w3-header-recovery.md)(과정)

> **결론 지향 문서.** 확정된 결과·수치·권고를 담는다. 과정의 가설·막다른 길은 [조사 기록](../investigations/2026-07-04-w3-header-recovery.md) 참조.

## 1. 한눈에 보기

**사용 가능한 사진(정상 복구본 + 손상 없던 원본)이 822장 중 681장(82.8%) → 740장(90.0%)으로 늘었다.**

| 분류 | W2 (전) | W3 (후) | 변화 |
|------|--------|--------|------|
| **사용 가능** (복구본 + 정상) | 681 | **740** | **+59** |
| 엔진 복구본(RECOVERED) | 539 | 537 | −2 |
| **헤더 복구본(HEADER_RECOVERED)** | 0 | **61** | **+61** |
| 손상 없던 원본(CLEAN) | 142 | 142 | 0 |
| 열지 못함(SKIP) — 산출물 없음 | 126 | **71** | **−55** |
| 복구 실패(FAILED) — 회색으로 끝남 | 15 | **11** | −4 |

> 헤더 복구본은 별도 분류(`HEADER_RECOVERED`)·별도 폴더(`header_recovered/`)로 저장된다.
> 엔진 복구본 −2는 원래 복구되던 2장이 헤더 재구성으로 더 나아져 이 분류로 옮겨진 것이다.

- **SKIP**(파일 앞부분이 깨져 그림을 아예 열 수 없던 파일)이 126장 → 71장으로 **55장 감소**.
- 그 55장 + 복구 실패 4장 + 기존 복구본 2장을 합쳐 **총 61장이 헤더 복구로 되살아났다.**
- **손상 없이 잘 복구되던 사진 중 나빠진 것은 0장**(회귀 0) — 신규 기능이 기존 결과를 망치지 않았다.

## 2. 배경·목적

JPEG 파일은 맨 앞에 **헤더**(그림의 해상도·색상 압축표 같은 설정 정보)를 두고, 그 뒤에 실제 그림
데이터를 담는다. 헤더가 손상되면 프로그램이 그림을 **읽기 시작조차 못 한다.**

기존 복구 엔진은 그림 데이터의 정렬 어긋남만 고칠 수 있었고, 헤더 손상은 손대지 못했다. 그래서
디스크에서 추출한 822장 중 126장(15%)이 "열 수 없음(SKIP)"으로 **산출물이 전혀 없었다** — 이들은
전부 헤더가 손상된 파일이다.

이번 작업(헤더 복구 pass)의 목적은 **손상된 헤더를 복원해 이 파일들을 복구 대상으로 되돌리는 것**이다.
같은 카메라로 찍은 다른 사진들의 헤더 정보를 참고 자료로 삼아 깨진 헤더를 재구성한다.

## 3. 방법

- **표본:** `output/jpeg/`의 추출 JPEG 822장(전수). W2·W3 모두 같은 822장에 같은 조건
  (`--time-budget 0` = 파일당 시간 제한 없음)으로 실행해 결과를 비교했다.
- **지표:**
  - **분류 건수** — 각 파일이 복구본/정상/열지못함/실패 중 무엇이 됐는지.
  - **미복구 회색 비율(undec)** — 복구 후에도 데이터가 없어 회색으로 남은 영역의 비율(0=완전 복구,
    1=전부 회색). 무채색 착시를 배제한 "진짜 복구율" 지표다.
  - **회귀** — W2에서 잘 복구되던 파일이 W3에서 나빠졌는지(미복구 회색이 늘었는지).
- **판정 기준(사전 합의):** ① 기존 복구본 회귀 0, ② 열지 못하던 파일의 복구 전환 수, ③ 복구된
  사진을 눈으로 확인해 실제 사진인지(엉뚱한 데이터로 채운 "가짜 복구"가 아닌지).
- **비교 원장:** `output/jpeg_recovered_w2/report.csv`(전) vs `output/jpeg_recovered_w3/report.csv`(후).

## 4. 결과

### 4-1. 61장이 되살아났고, 그중 45장은 사실상 완전 복구

되살린 61장의 복구 품질 분포(미복구 회색 비율 기준):

| 복구 품질 | 장수 | 의미 |
|-----------|------|------|
| 거의 완전 복구 (회색 5% 미만) | **45** | 사진 전체가 제대로 보임 |
| 부분 복구 (회색 5~50%) | 13 | 상당 부분 보이나 일부 회색 |
| 소량 복구 (회색 50% 이상) | 3 | 윗부분 일부만 살고 나머지는 데이터 소실 |

- **45장이 회색 5% 미만** = 열 수도 없던 파일의 74%가 사실상 온전히 되살아났다.
- 소량 복구 3장(회색 62~95%)은 헤더는 복원됐으나 그림 데이터 자체가 대부분 소실된 경우다 —
  데이터가 없어 더 살릴 수 없는 물리적 한계이며, 회색 비율이 결과 파일에 그대로 기록돼 있어
  얼마나 복구됐는지 투명하게 확인할 수 있다.

### 4-2. 손상 유형별 복구

헤더의 어느 부분을 복원했는지 조합별 분포(한 파일이 여러 부분을 동시에 복원하기도 한다):

| 복원한 헤더 부분 | 장수 |
|------------------|------|
| 해상도 정보(SOF)만 | 15 |
| 압축표(DHT) 이식만 | 11 |
| 4부분 전체(압축표+양자화표+해상도+스캔) | 13 |
| 그 외 조합 | 22 |

- 압축표(DHT)는 같은 카메라 사진들이 **모두 동일한 표준 표**(국제 표준 ITU T.81 Annex-K)를
  쓴다는 사실을 확인해, 그 표 하나를 코드에 내장해 이식했다.
- 양자화표(그림 압축 강도표)는 카메라 화질 설정마다 달라, 값이 튀는 이상치를 이웃 값으로
  보정하거나 같은 설정의 다른 사진 표를 가져와 복원했다.

### 4-3. 기존 복구본 회귀 0 (가장 중요)

W2에서 복구본/정상/실패였던 파일이 W3에서 **미복구 회색이 늘어난 경우는 0장**이다.

- 개발 중 회귀 1건(잘 복구되던 사진이 잘못된 해상도 추정으로 나빠짐)을 발견해, **이미 열리는
  파일은 헤더 복구가 기존 결과보다 나을 때만 적용**하도록 고친 뒤 재검증했다.
- **의미:** 신규 기능이 기존에 잘 되던 것을 건드리지 않는다 — 안전하게 배포할 수 있다.

### 4-4. 되살린 사진은 실제 사진 (가짜 복구 아님)

복구된 사진을 눈으로 확인한 결과, 되살린 파일은 모두 **실제 사진 내용**을 담고 있었다(엉뚱한
데이터로 회색만 지운 "가짜 복구"는 0장). 일부 사진에 남은 색 얼룩·가로 밀림은 이미 알려진 별개
과제(다음 단계 W4·W5)의 결함이며, 사진 내용 자체는 정상이다.

가짜 복구를 막기 위해, 복구 후보의 진위는 **그림의 겉모습(색·질감 통계)이 아니라 구조 신호**
(데이터를 얼마나 정상적으로 읽어냈는지)로만 판정한다. 겉모습 통계는 색 얼룩·밀림이 있는 상태에서
진짜 사진과 가짜를 구분하지 못하기 때문이다(상세: [ADR 0006](../adr/0006-header-recovery-structural-gates.md)).

## 5. 결론·권고

- **헤더 복구 pass는 복구 "파일 수"를 늘리는 가장 큰 레버였다** — 사용 가능한 사진이 822장 중
  681장 → 740장(82.8% → 90.0%)으로 올랐다. 세 차례 개선(W1~W3)을 거치며 76.6% → 82.8% → 90.0%로
  꾸준히 상승했다.
- **회귀 0 + 가짜 복구 0**으로 안전성이 확인됐으므로, 이 기능을 기본 복구 파이프라인에 포함할
  것을 권고한다.
- 남은 미해결은 **되살린 사진의 색 얼룩·가로 밀림**(다음 단계 W4·W5)이다 — 사진 내용은 살아났으나
  겉보기 품질을 더 다듬을 여지가 있다.

## 6. 한계

- **여전히 71장은 열지 못한다(SKIP).** 후속 감사([과다 카빙 조사](../investigations/2026-07-04-overcarve-buried-images.md))로
  정밀화하면 63장은 복원에 쓸 헤더 재료가 없고(사진이 아닌 데이터를 잘못 추출한 위양성 62 + 빈 조각 1),
  8장은 진짜 해상도 정보를 갖지만 스캐너·판정 한계로 미채택(그중 2장은 복구 가능) — 헤더 복구가 아니라
  추출 단계(carve) 정밀도의 문제다.
- **[후속 감사 발견] 헤더 복구 61장 중 3장(0x92EC750C·0xC8A59000·0xCA9C5000)은 과다 카빙 오분류다.**
  추출 단계가 연속된 여러 사진을 한 파일로 과다 추출한 덩어리를, 헤더 복구가 그중 한 장으로 채택한
  경우다(되살린 내용 자체는 실제 사진이라 §4-4의 "가짜 복구 0"은 유지). 이 3개 파일을 포함한 과다 추출
  덩어리 안에는 별도로 추출되지 못한 실제 사진 ~38장이 함께 들어 있다 — 추출 단계(carve) 정밀도 문제로,
  별도 항목(backlog C1)에서 재추출로 다룬다.
- **남은 복구 실패 11장**은 그림 데이터 뒷부분이 잘려 나갔거나 아주 작은 사진의 데이터 손상으로,
  더 살릴 데이터가 없는 물리적 한계다.
- 복구 품질은 카메라·손상 양상에 따라 다르며, 되살린 61장에도 색 얼룩·밀림이 남는다(위 5절).
- 이 수치는 **이 프로젝트의 특정 코퍼스(822장)** 기준이다 — 다른 카메라·다른 손상 분포에서는
  전환율이 달라질 수 있다.
