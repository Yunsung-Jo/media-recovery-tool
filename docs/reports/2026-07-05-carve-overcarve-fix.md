# 보고서 — 과다 카빙 수정: 묻혀 있던 사진 분리 추출로 사용 가능 사진 740→884(+144), 회귀 0

- **날짜:** 2026-07-05
- **대상/범위:** 디스크 이미지(`usb.img`, 3.5 GB)의 JPEG 추출·복구 — 과다 카빙 수정 전(W3) vs 후(C1), 동일 디스크·동일 복구 조건(`--time-budget 0`)
- **한 줄 요약:** 여러 사진을 **한 파일로 뭉쳐 추출**해 뒤 사진들이 사라지던 문제(과다 카빙)를 고쳐, 묻혀 있던 사진들을 따로 추출·복구했다. **사용 가능한 사진이 740장 → 884장(+144)**, 기존에 잘 나오던 사진은 **한 장도 잃지 않았다.**
- **관련 문서:** [ADR 0007](../adr/0007-carve-corrupt-header-boundary.md)(설계 결정)·[carve 스펙](../specs/0001-carve.md)(동작)·[C1 조사 기록](../investigations/2026-07-05-carve-overcarve-fix.md)·[과다 카빙 발견 조사](../investigations/2026-07-04-overcarve-buried-images.md)

> **결론 지향 문서.** 확정된 결과·수치·권고를 담는다. 과정의 가설·막다른 길은 [조사 기록](../investigations/2026-07-05-carve-overcarve-fix.md) 참조.

## 1. 한눈에 보기

**사용 가능한 사진(복구본 + 손상 없던 원본)이 740장 → 884장으로 144장 늘었다.**

| 분류 | W3 (전) | C1 (후) | 변화 |
|------|--------|--------|------|
| **사용 가능** (복구본 + 정상) | 740 | **884** | **+144** |
| ├ 엔진 복구본(RECOVERED) | 537 | 611 | +74 |
| ├ 헤더 복구본(HEADER_RECOVERED) | 61 | 86 | +25 |
| └ 손상 없던 원본(CLEAN) | 142 | 187 | +45 |
| 열지 못함(SKIP) — 산출물 없음 | 71 | 90 | +19 |
| 복구 실패(FAILED) — 회색으로 끝남 | 11 | 25 | +14 |
| 처리 중 오류(ERROR) | 0 | **0** | 0 |
| **추출 파일 합계** | 822 | 999 | +177 |

- **묻혀 있던 사진 144장이 사용 가능해졌다** — 육안 확인 결과 실제 개인 사진이다.
- **기존에 잘 복구되던 사진 중 잃은 것은 0장**(회귀 0) — 사라진 것처럼 보인 6장은 전부 다른 파일 안에 그대로 보존돼 있다(§4-2).
- 추출 파일이 822 → 999개로 는 것은, 뭉쳐 있던 덩어리를 여러 사진으로 **쪼갰기** 때문이다. 늘어난 열지못함(SKIP)·복구실패(FAILED)는 그 덩어리의 **손상된 앞부분 조각**으로, 원래도 묻혀서 못 쓰던 부분이다.

## 2. 배경·목적

디스크에서 사진을 추출하는 단계(carve)는 파일 하나의 **시작과 끝 위치**를 스스로 찾아야 한다
(파일 목록이 없는 손상 디스크이므로). 그런데 사진의 앞부분(헤더)이 손상돼 있으면, 추출기가 파일
끝을 잘못 계산해 **여러 사진을 한 파일로 통째로 삼켜** 버리는 일이 있었다. 이때 뒤에 있던 멀쩡한
사진들은 "이미 추출한 범위 안에 있다"고 판단돼 **따로 저장되지 않고 사라졌다.**

앞선 감사([과다 카빙 발견 조사](../investigations/2026-07-04-overcarve-buried-images.md))에서, 이렇게
한 파일에 묻혀 손실된 실제 사진이 큰 덩어리 5개에만도 62장 있었고, 작은 덩어리까지 포함하면 더
많음을 확인했다. 이번 작업(C1)의 목적은 **추출기가 파일 끝을 제대로 끊게 고쳐, 묻힌 사진들을 각각
따로 추출·복구하는 것**이다.

## 3. 방법

- **표본:** 디스크 이미지 `usb.img` 전체(3.5 GB)를 수정 전(W3)·후(C1) 각각 다시 추출·복구했다.
  복구는 양쪽 모두 같은 조건(`--time-budget 0` = 파일당 시간 제한 없음).
- **지표:**
  - **분류 건수** — 각 파일이 복구본/정상/열지못함/실패 중 무엇이 됐는지.
  - **사용 가능** — 엔진 복구본 + 헤더 복구본 + 손상 없던 원본. 실제로 볼 수 있는 사진 수.
  - **회귀** — 수정 전 잘 나오던 사진이 수정 후 사라지거나 나빠졌는지.
- **수정 내용:** 추출기가 사진 헤더를 훑을 때 **손상된 길이 표시나 엉뚱한 값**을 만나면, 무작정
  따라가지 않고 **다음 진짜 사진 시작점에서 파일을 끊도록** 했다(설계 근거: [ADR 0007](../adr/0007-carve-corrupt-header-boundary.md)).
- **비교 원장:** `output/jpeg_recovered_w3/report.csv`(전) vs `output_c1/jpeg_recovered/report.csv`(후).

## 4. 결과

### 4-1. 사용 가능한 사진 144장 증가

수정 후 사용 가능한 사진이 740장 → 884장으로 늘었다. 내역은 엔진 복구본 +74, 헤더 복구본 +25,
손상 없던 원본 +45장이다. 이들은 전에 한 파일에 뭉쳐 묻혀 있던 사진들이 각각 분리·복구된 것으로,
육안 확인 결과 실제 개인 사진이다.

### 4-2. 기존 복구본 회귀 0 (가장 중요)

수정 전 사용 가능하던 740장 중, 수정 후 **내용이 사라진 것은 0장**이다.

- 파일 위치상 사라져 보인 6장은 전부 다른 사진의 **EXIF 썸네일**(사진에 딸린 축소 미리보기)이었고,
  그 사진(부모 파일)이 복구되면서 **같은 미리보기 내용이 그대로 보존**된다.
- 분류가 바뀐 5장은, 수정 전 여러 사진이 뭉친 덩어리를 **하나의 사진으로 잘못 복구**했던 것을,
  수정 후 **여러 개로 제대로 쪼갠 것**이다(그중 하나는 수정 전에 거의 회색이었고 수정 후 더
  선명해졌다). 즉 회귀가 아니라 **잘못 뭉쳤던 것의 교정**이다.
- **의미:** 신규 수정이 기존에 잘 되던 것을 망치지 않는다 — 안전하게 배포할 수 있다.

### 4-3. 처리 중 오류 0 (안정성)

수정 중, 손상돼 잘려 나간 조각이 복구 프로그램을 **멈추게 하는 오류**(파일 헤더를 읽다 데이터
범위를 벗어남)를 하나 발견해 함께 고쳤다. 그 결과 999개 전부 오류 없이 처리됐다(ERROR 0). 이
오류가 재발하지 않도록 검증 테스트 4개를 추가했고, 전체 테스트 65개가 통과한다.

## 5. 결론·권고

- **과다 카빙 수정은 복구 "사진 수"를 늘리는 큰 레버였다** — 사용 가능한 사진이 740장 → 884장으로
  144장 늘었고, 이는 추출 단계에서 묻혀 손실되던 사진을 되살린 것이다.
- **회귀 0 + 오류 0**으로 안전성이 확인됐으므로, 이 수정을 기본 추출 파이프라인에 포함할 것을 권고한다.
- 남은 미해결은 아래 한계와, 별도 항목(헤더가 손상된 파일의 저장 방식 개선 등)이다.

## 6. 한계

- **사용 가능 "비율"은 90.0% → 88.5%로 내려간 것처럼 보인다.** 이는 나빠진 게 아니라, 수정으로
  뭉친 덩어리를 여러 파일로 쪼개면서 **분모(전체 파일 수)가 822 → 999로 늘었기** 때문이다. 늘어난
  파일 중 열지못함·복구실패로 분류된 조각들은 덩어리의 손상된 앞부분으로, 원래도 못 쓰던 부분이다.
  실제 성과는 비율이 아니라 **사용 가능한 절대 장수(+144)**로 봐야 한다.
- **아주 작은 이미지 소수는 다른 것으로 대체됐다.** 손상된 앞부분 사진 대신 뒤의 더 깨끗한 사진이
  추출되는 경우가 소수 있었다 — 잃은 쪽은 작은 미리보기급이라 손실 영향은 작다.
- **사진이 아닌 데이터를 사진으로 오인 추출한 파일(위양성)** 일부가 수정 후 최대 10 MB까지 커져
  디스크를 더 쓴다(복구 결과엔 영향 없음, 열지못함 유지).
- 이 수치는 **이 프로젝트의 특정 디스크(`usb.img`)** 기준이다 — 다른 카메라·다른 손상 분포에서는
  성과가 달라질 수 있다.
