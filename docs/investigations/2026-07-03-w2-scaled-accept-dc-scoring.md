### 2단계 — 물리 채점 보정 측정: 절대 경계 기각 정책은 정당 세그먼트를 오기각한다

- **가설 / 세운 이유:** 물리 채점 정책을 정하기 전에, **현재 수락돼 있는 정당한 세그먼트들**이
  물리 신호(절대 경계 |dequant DC| > 1024+q0/2 위반 비율, per-comp 스팬 max−min > 2040+q0)를
  얼마나 위반하는지 측정해야 한다 — DC=0 리셋 세그먼트는 절대 오프셋을 잃으므로([blocky 조사]
  5단계: 세그 평균 Cb −1055 관측) 정당해도 절대 경계를 위반할 수 있다. 위반이 크면 절대 경계
  기각 정책은 회귀를 만든다.
- **실험:** 가드 3건(0xBA5F6000·0xA1F57000·0xCCAFF000)에 본체 recover를 재실행(`calibrate_phys.py`,
  blocky 조사 ①과 같은 buf 반환 하니스), 수락된 세그먼트별로 최종 render의 MCU별 dequant DC에서
  per-comp absviol 비율·스팬을 집계.
- **예측:** zero 리셋 세그먼트의 Cb/Cr absviol이 상당(>0.1)할 것. 스팬은 참 DC 스팬 ≤2040이므로
  대체로 한계 내일 것.
- **증거:** 예측 반쪽만 맞음 — **위반이 예상보다 훨씬 크고 스팬도 무너져 있다.**
  - absviol: 0xA1F57000 seg1(carry) Cr **0.88**, seg4(zero) Y **0.56**, seg21(carry, 0xBA5F6000) Cb
    **0.73** 등 — zero뿐 아니라 carry·seg0(정정렬)까지 광범위(seg0 Cb 0.33).
  - 스팬: Y 스팬이 2040+q0을 넘는 세그먼트 다수(최대 2787; seg0조차 2129~2670) — 세그먼트가
    길고(≤12642 MCU) 내부에 불완전 편집(sub 26~28)의 잔존 DC 오차가 누적되기 때문.
    참 DC 스팬 ≤ 2040은 **편집 없는 구간**에서만 보장된다.
- **판단:** **절대 경계 viol 비율로 후보를 기각하는 정책은 기각** — 현재 정당하게 수락되는
  후보(오프셋 오차 보유)를 대량 오기각해 회귀를 만든다. 스팬도 세그먼트 전체 단위로는 판별력이
  오염된다(편집 오차). 물리 채점을 쓴다면 ① probe 창(편집 없는 직선 디코드) 한정 + ② 오프셋
  무관량(스팬)으로, 그리고 ③ 기각이 아니라 **포화 동률 후보 간 순위**(tie-break)로만 —
  가부는 3단계(실측 판별력)에서. 교훈: **복구 엔진이 만든 출력은 물리 불변량을 이미 위반한다
  (리셋 오프셋·편집 잔존 오차) — 불변량 검사는 반드시 원시 스트림 성질이 보존되는 범위(무편집
  probe 창)에 한정해 적용하라.**

### 3단계 — 미개선 4건의 정지 원인: frontier 후보 전수 스캔

- **가설 / 세운 이유:** 사이클 1에서 0xC8069000·0xC9CD0000·0xB164690C·0xCE2DF000이 스케일
  임계로도 ops 0·hole 1. 후보 스캔의 최대 clean run이 수락 임계에 못 미친다는 뜻인데, 그 원인이
  (a) 데이터 소실(어느 정렬에서도 이어지는 콘텐츠 없음 — 0xC8069000 소비 88.8% 의심),
  (b) 연속 손상 간격이 여전히 임계 미만(best run이 임계 바로 아래 — 임계 추가 인하+채점으로
  구제 가능), (c) 헤더 손상(0xB164690C — 사각지대 조사 6~7단계에서 단일 DHT 지문·이식 시
  20/30 디코드, W3 대상)인지 갈라야 다음 레버가 정해진다.
- **실험:** 각 파일 frontier에서 `_resync_skip`과 동일한 스캔(near 300000 byte정렬 + 전체 64비트
  거친 스캔, DC 캐리/zero)을 수행하되 수락 대신 **후보 분포를 기록**: best 15(run·db·dc종류),
  run≥30/100/200/임계 후보 수, frontier 소비율(mb[frontier]/nbits). 상위 후보에는 probe 창
  물리 신호(absviol·스팬)도 기록(3단계 판별력 데이터 겸용).
- **예측:** 0xC8069000 best run < 92(수락 임계) 산발 — (a) 판정. 0xC9CD0000 best run 100~340
  (임계 347 미만) — (b) 판정. 0xB164690C best run < 30 — (c) 판정(첫 MCU부터 경계 발동).
  0xCE2DF000은 미지 — best run이 임계(0.55·W) 근처면 (b).
- **증거:** (`analyze_frontier.py`, probe 창 물리 신호 = absviol MCU 수(viol)·per-comp dequant DC 스팬)
  - **0xC8069000** (total 300, frontier **46**, W 254, accept 139, frontier 소비율 0.125): best run
    **105**(db≈+29040, stop=2 계수경계) — 후보 클러스터(db 29040~30016)가 동일 스팬(Y 1875/Cb 540/Cr
    945, 전부 물리 내)으로 수렴 = 진짜 재개 지점으로 보임. run≥100 후보 172, ≥200은 0. **같은
    비트에서 zero 후보 viol 0~11 vs carry 후보 viol 48~57** — 물리 신호가 DC 후보를 가른다(현행
    동률 규칙은 carry 우선이라 오프셋 오차 쪽을 채택하게 됨). 105 MCU 뒤 또 손상 → **다중 손상
    사슬, 간격 105 < 임계 139**. 참고: 선행 조사의 "소비 88.8%"는 plain full 디코드 end_bit
    기준(드리프트 포함)이고 frontier 소비율은 0.125 — 데이터는 충분히 남아 있다.
  - **0xC9CD0000** (total 638, frontier 7, W 631, accept 347): best run **294, stop=3(버퍼 끝)**
    (db≈+232608) — **남은 데이터 전체가 프레임 완주 없이 소진되는 절단 파일**(0xC8~0xC9 대역
    EOI 부재 절단군)이지만, 남은 294 MCU 분량은 이어져 디코드된다. 294 < 347이라 거부 중.
    같은 비트에서 **carry viol 0 vs zero viol 143**, 스팬 Y 1810/Cb 355/Cr 480 물리 내.
  - **0xB164690C** (total 30, frontier 0): **run≥20 후보 전무**(전 스트림·양 DC) — 자체 DHT로는
    어떤 정렬도 20 MCU를 못 간다. (c) 헤더 손상 확정([사각지대 조사] 6~7단계의 단일 지문·이식 시
    20/30과 정합) — **W3 대상, W2 범위 밖.**
  - **0xCE2DF000** (total 1200, frontier 752, W 448, accept 246, 소비율 0.665): best run 167
    클러스터(db≈+30680~32832) **전원 span Y 2620~2656(물리 불가 > 2040+q0)**, viol 5~14.
    run≥100 후보 3774, ≥200은 0. — 임계를 167 이하로 내리면 물리 불가 후보가 수락될 사례
    = **스팬 기각 없인 임계 인하가 masking을 만든다는 실증.**
- **판단:** 가설 (a)는 4건 모두 기각·정정 — 실체는 (b) 간격<임계 2건(0xC8069000 105/139,
  0xC9CD0000 294/347·데이터-끝 완주), (c) 헤더 손상 1건(0xB164690C), (d) **물리 불가 후보만 남은
  데이터 한계 1건**(0xCE2DF000 — 스팬 기각의 정당성 실증). 물리 신호의 실제 판별 사례 3종 확보:
  ① 동일 run 동률에서 DC 후보 선택(carry↔zero, viol), ② 물리 불가 정렬 기각(스팬), ③ 데이터-끝
  완주 run의 특수 취급(stop=3). 다음: 이 신호들이 **기존 수락 후보를 오기각하지 않는지**(안전성)
  가드·실증 4건의 수락 시점 probe 창에서 검증(4단계).

### 4단계 — 스팬 기각의 안전성: 기존 수락 후보의 probe 창 스팬 측정

- **가설 / 세운 이유:** 3단계에서 스팬(무편집 probe 창의 per-comp dequant DC max−min)이 물리 불가
  정렬을 가른다는 실증(0xCE2DF000)을 얻었다. 스팬 기각을 채점에 넣으려면 **현재 정당하게 수락되는
  후보들이 수락 시점 probe 창에서 스팬 한계(2040+q0)를 넘지 않아야** 한다(참 DC 스팬 ≤ 2040은
  오프셋 무관·무편집 구간에서 보장 — 2단계의 세그먼트 전체 위반은 내부 편집 오차 때문이므로
  probe 창에는 적용되지 않을 것).
- **실험:** 하니스 probe를 스팬·정지사유 추적 버전으로 교체(`decode_probe_dc` — 동작 불변, 로깅만),
  사이클 1과 동일 파라미터 + `phys=auto`로 14건 재실행. 수락된 재동기 후보 전건(가드 39 + 실증 4)의
  probe 창 스팬을 기록.
- **예측:** ① 14건 지표는 사이클 1과 완전 동일(로깅만 추가). ② 수락 후보 전원 per-comp 스팬
  ≤ 2040+q0 — 하나라도 넘으면 스팬 "기각"은 회귀를 만들므로 순위 강등으로 후퇴해야 한다.
- **증거:** 예측 ① 적중(14건 지표·ops 구성 사이클 1과 동일). **예측 ② 결정적으로 반증** —
  수락 52건(실증 4 + 가드 15/24/9) 중 **31건이 물리 한계 초과 스팬 보유**(Y>2050 30건 + Cb 1건):
  - 실증 4 중 1건: 0xC8BC4000 수락 후보(run 378, 최종 undec 0.087·육안 통과 = 명백한 정당 복구)가
    **span Y 2370, viol 233/378(62%)**.
  - 0xA1F57000 15건 중 13건 위반(Y 최대 2723, viol 최대 849/900), 0xBA5F6000 24건 중 12건(Y 최대
    2715), 0xCCAFF000 9건 중 5건(Y 최대 2690).
  - 반면 3단계에서 "물리 불가"로 본 0xCE2DF000 후보(span 2620, viol 5~14)와 수치 범위가 **겹친다** —
    good(2370~2723) vs suspect(2620), viol은 오히려 good 쪽이 큼(62% vs 3~8%).
- **판단:** **스팬 하드 기각·viol 비율 기각 모두 전면 기각.** 원인 해석: probe의 "clean run"은
  plausibility 경계(±1400) 안의 잔존 드리프트를 포함한다 — 손상 파일의 수락 후보 창은 pristine한
  적이 없고, 물리 불변량 위반이 오히려 일상적이다(수락 52건 중 31건). 물리 신호로 good/bad
  후보를 가를 수 없다. **물리 채점의 유효 역할은 "같은 비트에서 carry↔zero DC 후보 동률 선택"으로
  축소**된다(3단계 실증: 0xC8069000 zero viol 1 vs carry 55, 0xC9CD0000 carry 0 vs zero 143 —
  같은 비트열·같은 정렬이라 viol 차이가 순수하게 DC 시작값 품질을 반영). 한계 후보의 수락 여부는
  물리 신호가 아니라 **직접 렌더 육안 판정**으로 정해야 한다(5단계).

### 5단계 — 한계 후보 3건 직접 렌더: 수락했다면 무엇이 나오나

- **가설 / 세운 이유:** 4단계에서 물리 필터가 죽었으므로, 3단계의 한계 후보들(임계 미달로 거부
  중인 best run)이 **실제로 수락됐다면 좋은 복구였을지**를 임계 기계를 우회해 직접 확인한다 —
  세그먼트를 수동 구성해 렌더. 이 결과가 임계 정책(어디까지 내릴 수 있나)의 근거가 된다.
- **실험:** 각 파일에 세그먼트 `[(0,0,0), (m_d, mb[m_d]+db, dc)]`를 수동 구성해 엔진과 동일한
  최종 렌더(`_decode_traj` stop=True) 후 undec 측정·PNG 저장:
  0xC8069000 (46, +29040, zero) / 0xC9CD0000 (7, +232608, carry) / 0xCE2DF000 (752, +30680, zero).
- **예측:** 0xC8069000 undec 0.843→≈0.50(151/300 디코드), 콘텐츠 고주파 비반복(진짜 재개점 —
  후보 클러스터 수렴·스팬 정상). 0xC9CD0000 0.988→≈0.53(301/638), 진짜 콘텐츠(데이터-끝 완주).
  0xCE2DF000 0.373→≈0.235(919/1200) — **진위 예단 불가**(스팬 신호 사망), 육안 판정이 이 실험의
  목적.
- **증거:** undec 예측 3건 전부 적중 — 0xC8069000 0.843→**0.497**(frontier 151/300),
  0xC9CD0000 0.988→**0.523**(301/638), 0xCE2DF000 0.373→**0.234**(919/1200).
  육안(결함 패턴): **3건 모두 재개 세그먼트가 고주파 비반복 콘텐츠** — masking형(주기 반복·평탄
  단색) 아님. 0xC8069000은 세그먼트 색 캐스트(zero 시작), 0xCE2DF000도 실질 구조 + 강한 색
  캐스트(스팬 2620 후보였음 — 위반은 창 내 드리프트/오프셋 탓, 4단계 결론과 정합).
- **판단:** **3건 모두 진짜 재개점 — 이들의 유일한 장벽은 수락 임계다.** 표본 내에서 "손상
  지점의 best-run 후보가 garbage였던 사례"는 아직 0건(실증 4 + 이번 3). 0.55W(실증값)는
  보수적이며 추가 인하 여지가 있다: 0xC8069000 105=0.41W, 0xCE2DF000 167=0.37W,
  0xC9CD0000 294=0.47W·stop=3(데이터-끝 완주 — 뒤에 가릴 데이터 자체가 없어 masking 불가능한
  특수형). 다음: 임계 0.35W + 데이터-끝 완주 규칙으로 전 샘플 재실행(6단계).

### 6단계 — 임계 0.35W + 데이터-끝 완주 규칙

- **가설 / 세운 이유:** 5단계에서 한계 후보 3건 전부 진짜로 판정. 수락식을
  `run ≥ max(30, 0.35W)` **또는** `stop=3(버퍼 끝 완주) & run ≥ 30`으로 완화하면 3건이 수락되고,
  표본 근거상(불량 best-run 후보 0건) 가드 회귀는 없을 것.
- **실험:** `recover_scaled(accept_frac=0.35, stop3_rule)`로 14건 전체 재실행(물리 채점 off —
  임계 단일 변수). 수락 후 사슬(다음 frontier에서 재시도)이 자동으로 이어진다.
- **예측 (실험 전 기록):**
  - 0xC8069000 ≤0.497(첫 수락 105 후 사슬이 더 이어질 수 있음), 0xC9CD0000 ≈0.523,
    0xCE2DF000 ≤0.234(사슬 여지).
  - 실증 4건: 기존 수락 유지, 최종 hole 지점에서 추가 수락 가능 → undec 같거나 감소.
  - 0xB164690C 불변 1.000(run≥30 후보 전무 — 헤더 손상).
  - 가드: 대형 수락 임계 495→315지만 기존 수락 run 전부 540~900이라 동일 지점 수락 유지.
    최종 hole에서 추가 수락 가능성(0xA1F57000·0xCCAFF000) → undec 같거나 감소, **증가하면 회귀**.
    0xBA5F6000(데이터 소진)·소형 3건·CLEAN 불변.
- **증거:** 예측 전부 적중.
  - **전환 3건:** 0xC8069000 0.843→**0.220**(수락 2회 사슬: 46/+29040/run105 + 151/+28152/run83
    stop=3), 0xC9CD0000 0.988→**0.523**(7/+232608/run294, 294≥0.35W=220이라 stop3 규칙 불요였음),
    0xCE2DF000 0.373→**0.118**(수락 2회: 752/+30680/run167 + 919/+53560/run140 stop=3).
  - 실증 4건: 수락 지점·run·undec 사이클 1과 동일(0.004/0.181/0.087/0.316).
  - 0xB164690C 1.000 불변. **가드 6건 지표·ops 구성·수락 지점 전부 베이스라인과 동일**(최종 hole
    추가 수락 없음 — 후보 자체가 없는 지점들) — 회귀 0.
- **판단:** 지지 — `max(30, 0.35W)` + 데이터-끝 완주(stop=3 & run≥30) 규칙으로 샘플 실패군
  7건 중 6건이 undec 0.004~0.523(잔여는 데이터 한계·절단 몫), 나머지 1건(0xB164690C)은 W3(헤더)
  대상. 다음: 같은 비트 DC 후보 동률 tie-break(7단계)로 색 캐스트/클리핑 축소.

### 7단계 — 같은 비트 DC 후보(carry↔zero) 동률 tie-break: viol 최소 선택

- **가설 / 세운 이유:** 3단계에서 같은 비트의 carry/zero 후보가 run 동률일 때 viol이 크게
  갈렸다(0xC8069000: carry 55 vs zero 1). 현행 규칙은 동률 시 먼저 probe한 carry를 유지하므로
  물리적으로 불가능한 DC(→ 렌더 클리핑, 후처리 색 보정으로도 복원 불가한 손실)를 채택할 수 있다.
  같은 비트열·같은 정렬에서 DC 시작값만 다르므로 **viol 차이는 순수하게 DC 시작값 품질**을
  반영한다 — 4단계에서 기각된 "필터" 용법과 달리, 동률 선택은 수락 집합을 바꾸지 않아 회귀
  위험이 없다. 스캔 비용도 최종 선택 비트에서 물리 probe 2회뿐.
- **실험:** `dc_tiebreak=True`(수락 직전 최종 비트에서 carry/zero를 물리 probe로 재평가, run 동률
  최대인 것 중 viol 최소 채택)로 14건 재실행. 나머지 파라미터는 6단계와 동일(0.35W + stop3).
- **예측:** ① undec은 전 파일 6단계와 동일(DC 시작값은 색만 바꿈). ② 0xC8069000 첫 수락이
  carry→zero로 flip(캐스트 감소, 육안). ③ 0xC9CD0000은 carry 유지(viol 0). ④ 가드 대형의 포화
  동률 세그 일부 carry→zero flip 가능(예: 0xA1F57000 m_d=12642, 4단계 viol 849) — undec 불변,
  색 변화만.
- **증거:**
  - ① 대체로 적중: 13/14 undec 동일, 0xBA5F6000만 0.041→0.040(-0.001, 허용 내).
  - ② 적중: 0xC8069000 첫 수락 carry(viol 55)→zero(viol 1) flip. 단 **육안(결함 패턴)은 개선
    불명확** — 세그 캐스트의 색조만 변화(계열 이동), 캐스트 강도는 유사.
  - ③ 적중(carry 유지, viol 0).
  - ④ 부분: 0xA1F57000 m_d=12642는 carry 유지(zero가 그 비트에서 run<900 = 진짜 동률 아님,
    tie-break는 진성 동률만 건드림을 확인). 반면 0xBA5F6000은 동률 flip 여러 건(zero↔carry 양방향,
    예: m_d=39546 zero→carry (604,-259,270))으로 **중반 이후 궤적이 갈라져** 편집 구성까지 변화
    (sub 26→30, resync 24→23), undec 0.040 동등. 육안 우열 없음(밴드별 캐스트 계열만 상이).
- **판단:** 동작은 설계대로이나 **W2 이식에서 제외**한다. 근거: (a) 기준 B(undec·전환)에 기여 0,
  (b) 육안 이득 미검증(캐스트는 오프셋 자체가 미지라 어느 상수를 골라도 잔존 — 근본 해결은 W5
  오프셋 보정), (c) 전수 적용 시 기존 RECOVERED 다수의 출력이 무작위로 미세 변화해 W1 대비 회귀
  판정이 흐려짐. viol 감소(클리핑 손실 축소)는 실측 사실이므로 **W5(색 캐스트 보정)와 결합해
  재평가하도록 백로그에 라우팅**(클리핑은 W5의 상수 덧셈으로 복원 불가한 손실이라, W5 시점에
  tie-break를 켜는 것이 잠재 이득).

### 8단계 — AC 경계 마진 재점검 (백로그 W3 흡수 항목, 병행 측정)

- **가설 / 세운 이유:** [blocky 조사] 4단계에서 0xC93EC000 max|AC| 6052(=356×q17)가 AC_BOUND
  6000을 1계수 넘는 관측이 있어 "정상 계수를 자르는 마진 부족" 의심이 남아 있었다.
- **실험:** 손상 없는 CLEAN 143건의 plain 디코드에서 파일별 max dequant |AC| 분포 측정.
- **예측:** 정상 콘텐츠의 max|AC|가 6000에 근접(>5500)하는 파일이 여럿이면 마진 부족이 사실.
- **증거:** CLEAN 143건 max|AC|: **최대 3240**(0xC7FEE000), 2위 1794, 중앙값 532. >5500은 0건.
- **판단:** **AC_BOUND 6000은 이 코퍼스의 정상 계수를 자르지 않는다**(최대 관측의 1.85배 여유).
  6052 관측은 드리프트 구간 소산으로 재해석 — 경계 변경 불요, 항목 종결.

### 9단계 — 전체 적용: 이식 → 샘플 재검증 → 전수 822건

- **실험:** 6단계 정책(0.35W + 데이터-끝 완주, tie-break 제외)을 `carver/resync.py`에 이식
  (`_probe_stop` 추가, `_resync_skip` 수락식, `recover`의 W 캡·편집 임계), 테스트 2종 추가
  (0xFE 채움 hole — cat-10 DC 코드 연쇄로 계수 경계를 결정적으로 발동; 무작위 손상은 조밀 코드
  공간 탓에 조용히 디코드돼 테스트 재료로 비결정적임을 확인). 본체로 샘플 14건 재검증 후
  전수 실행(`recover.py output/jpeg -o output/jpeg_recovered_w2 --time-budget 0`, -j 12).
- **예측:** 샘플 14건 하니스(사이클 6)와 완전 일치. 전수에서 FAILED 66건 중 상당수 전환,
  파일별 undec_after 악화 신규 0.
- **증거:**
  - 테스트 58개 전부 통과. **샘플 재검증 14/14 하니스와 완전 일치**(undec·ops 구성).
  - 전수(822건, 17분 35초): **RECOVERED 539 / CLEAN 142 / FAILED 15 / SKIP 126**
    (W1: 487/143/66/126). 전이는 FAILED→RECOVERED **51**, CLEAN→RECOVERED 1
    (0xC7FEE000 — 스케일 편집 임계로 sub 1 수락, hole 렌더 undec 0.195→**0.000** 완전 복구),
    나머지 전부 유지.
  - **기준 A: 파일별 undec_after 악화(+0.01 초과) 0건.** 개선 65건 / 악화 0건.
  - **기준 B:** RECOVERED+FAILED undec_after 합 **47.38→24.05**(−49%). MCU 대역별 평균:
    120–449 **0.121→0.018**, 450–899 **0.176→0.046**, ≥900 0.044→0.041, <120 0.155 불변
    (96×72 DHT 손상군 — W3 대상). worse 플래그 67→38: RECOVERED 27건 = W1 worse 승계 13 +
    전환 파일의 undec_before 착시 14(드리프트 스트림의 plain "완전 디코드"가 undec 0으로
    측정되는 지표 한계), **신규 0**.
  - FAILED 잔여 15건: 96×72(30 MCU) 10건 + 50×50(16 MCU) 1건 = 헤더 손상·초소형(W3),
    중형 4건(0xC15FD000 undec 0.004 — 사실상 정상, 0xC81B8000 0.059, 0xC87D2000 0.622,
    0xC9866000 0.729 — 345×459 절단군).
  - **기준 C:** 전환 51건 중 표본 12건(MCU 150~1200, 신규 파일 위주) 몽타주 — **전부 실제
    고주파 비반복 콘텐츠, masking형 0건.** 잔여 결함은 세그먼트별 색 캐스트·수평 밀림 밴드
    (기지 W4·W5 유형)와 데이터 한계 잔여 회색.
- **판단:** 성공 종료 — 기준 A(회귀 0)·B(최소선 초과: 전환 51/66, undec 합 −49%)·C(masking 0)
  모두 충족. 샘플이 전체를 대표함도 확인(전수 실패 없음 → 루프 재진입 불요).

## 기각된 가설 / 막다른 길

- **절대 물리 경계(1024+q0/2) 위반 비율로 재동기 후보 기각 → 기각(2단계).** 정당 수락 세그먼트의
  absviol이 최대 0.88(carry)·0.73(zero) — 리셋 오프셋·편집 잔존 오차 때문. 교훈: 복구 출력은
  물리 불변량을 이미 위반하므로, 절대 경계 검사를 복구물에 적용하지 말 것.
- **스팬(오프셋 무관 불변량, 무편집 probe 창 한정) 하드 기각 → 기각(4단계).** 정당 수락 후보
  52건 중 31건이 스팬 한계 초과(0xC8BC4000 2370, 가드 최대 2723) — probe의 "clean run"은
  plausibility 경계(±1400) 안의 잔존 드리프트를 포함하므로 창이 pristine하지 않다. 교훈:
  **물리 불변량은 인코더 원본 스트림에만 성립한다 — 복구 후보의 probe 창조차 잔존 드리프트를
  포함하므로, 불변량은 필터가 아니라 동일 정렬 내 상대 비교(같은 비트의 DC 후보 간)에만 유효하다.**
- **"스팬 2620 후보(0xCE2DF000) = 물리 불가 garbage" (3단계 판단) → 반증(5단계).** 직접 렌더
  결과 실질 콘텐츠 + 색 캐스트(undec 0.373→0.234). 교훈: 물리 신호로 후보 진위를 예단하지 말고
  **한계 후보는 세그먼트 수동 구성 직접 렌더로 판정하라**(비용 수 초, 확정적).
- **"0xC8069000 재동기 불가 = 데이터 소실 의심" (선행 [사각지대 조사] 4단계) → 정정(3단계).**
  frontier 소비율 0.125, best run 105의 수렴 클러스터 존재 — 다중 손상 사슬(간격 105 < 임계)이었고
  임계 인하로 undec 0.220까지 복구. 교훈: plain 디코드 소비율(88.8%)은 드리프트를 포함하므로
  데이터 소실 판정에 쓰지 말고 **frontier 시점 소비율**로 판정하라.
- **DC 후보 동률 tie-break(viol 최소) 즉시 이식 → 보류(7단계).** undec 기여 0, 육안 이득 불명확,
  전수 diff 소음. W5(색 보정)와 결합 재평가로 백로그 라우팅. 교훈: **지표(A·B)에 기여 없는 품질
  레버는 그 품질축을 직접 다루는 작업과 묶어 평가하라** — 단독으로는 판정 기준이 없다.

## 사용한 방법·도구

전부 scratchpad `w2/`(세션 종료 후 소멸 — 재현 핵심은 아래와 본문 수치):

- `baseline_w2.py` — 샘플 14건 현행 엔진 재실행 + W1 report 대조 + before/after 렌더·몽타주.
  리포 루트에서 `python -X utf8 <script>`, recover는 전부 `time_budget=0`.
- `harness.py` — `recover_scaled`: 본체 `recover`/`_resync_skip` 복제 + 파라미터화(임계 스케일
  `accept_frac`·`accept_floor`, 데이터-끝 완주 `stop3_rule`, DC 동률 `dc_tiebreak`, 물리 채점
  `phys`/`viol_max`/`span_reject`) + 수락 로그(m_d/db/run/accept/W/viol/span/stop/dc0).
  `decode_probe_dc`(njit): 본체 `decode_probe` + 절대위반 MCU 수 + per-comp dequant DC 스팬.
  `run_samples(tag, **kw)`로 샘플 일괄 실행·렌더·metrics.csv.
- `calibrate_phys.py` — 가드 3건 본체 recover 재실행 후 수락 세그먼트별 absviol·스팬 집계(2단계).
- `analyze_frontier.py` — frontier에서 `_resync_skip` 동일 스캔의 후보 분포(run 상위 15 +
  물리 신호) 기록(3단계).
- 한계 후보 직접 렌더(5단계): 세그먼트 `[(0,0,0),(m_d,mb[m_d]+db,dc)]` 수동 구성 →
  `_decode_traj`(stop=True) → undec·PNG.

## 결론

**최종 정책(샘플 검증 완료, 이식 대상):** 각 디싱크 지점 m_d에서 잔여 rem = 총MCU − m_d,
probe 캡 `W = min(900, rem)`으로:

| 항목 | 현행(본체) | 변경 |
|------|-----------|------|
| resync 수락 | `run ≥ max(250, maxW//2)` (=450) | `run ≥ max(30, 0.35·W)` **또는** `stop=버퍼끝 & run ≥ 30` |
| 편집 수락 | `run > 120` | `run > min(120, max(20, 0.4·rem))` |
| 편집 개선폭 | `base + 30` | `base + min(30, rem//4)` |
| masking 가드 | `\|db\| ≥ 24` | 유지 |

1. **수락 임계 잠금은 잔여 비례화 + 데이터-끝 규칙으로 풀린다.** 샘플 실패 8건 중 6건 전환
   (0.961→0.004, 0.928→0.181, 0.799→0.087, 0.750→0.316, 0.843→0.220, 0.988→0.523, 0.373→0.118 —
   마지막 셋은 사슬 수락 포함), 1건은 W3(헤더) 대상, 가드 6건 회귀 0. 잔여 undec는 절단·데이터
   한계 몫. **전수 822건(9단계): FAILED 66→15(RECOVERED 전환 51 + CLEAN→RECOVERED 완전 복구 1),
   파일별 undec 악화 0건, RECOVERED+FAILED undec 합 47.38→24.05, 전환 표본 12건 masking 0건.**
   잔여 FAILED 15건 = 헤더 손상·초소형 11(W3) + 사실상 정상 1 + 절단·데이터 한계 3.
2. **DC 물리 범위는 수락/기각 필터로 쓸 수 없다**(2·4단계 — 정당 후보의 위반이 일상적). 유효
   용법은 ① 같은 비트 DC 후보 동률 선택(7단계 — W5와 결합 재평가로 백로그), ② 진단·분석 신호
   (3단계 — frontier 원인 분류에 실효). 백로그 W2의 전제("물리 채점이 임계 인하의 안전장치")는
   **기각되었고, 임계 인하는 채점 없이도 표본 내 안전**(불량 best-run 후보 0건, 가드 회귀 0)이
   실증됐다. 전수 적용의 안전망은 파일별 undec 회귀 diff + 저임계 수락 표본 육안으로 확보한다.
3. **AC_BOUND 6000 변경 불요**(8단계 — CLEAN 143건 max|AC| 3240, 여유 1.85배).
4. off-target 라우팅: DC tie-break→백로그(W5 결합), 0xB164690C류 DHT 손상→W3(기존 항목).
