### 1단계 — DHT 이식: 도너 대결(자체 vs 이식) probe로 채택·보호를 한 규칙에 담는다

- **가설 / 세운 이유:** 0단계에서 도너 DHT는 전역 단일(050df0dc)이고, 보호해야 할 정상 이탈 9건은
  자체 DHT로 완전 디코드된다. 따라서 "자체 헤더 probe run vs 도너 이식 probe run"을 **같은 잣대로
  대결**시키면 — ① 구성 불가 파일(DHT 소실)은 자체 run이 존재하지 않아 도너가 이기고, ② 손상 DHT
  파일(FAILED 지문 이탈)은 자체 run이 계수 경계에 걸려 짧아(쓰레기 디코드) 도너가 이기고, ③ 정상
  이탈 파일은 자체 run이 도너보다 길어 자체가 이긴다(회귀 자동 방지). 판정 신호는 W2에서 검증된
  probe(경계+rate)를 그대로 쓴다.
- **실험:** scratchpad `w3/harness.py` — `make_decoder(data, huff_override)`(사각지대 조사 ②의
  `__new__` 우회 스니펫 재사용), `probe0`(bit 0·MCU 0·DC 0에서 `decode_probe`, 경계·rate는 엔진과
  동일: `rate=max(350, nbits/total·4)`, `maxW=min(900,total)`), `plain`(decode_full →
  done/err/undec). 샘플 중 DHT군 4(0x95AAD000·0xCA9AA000·0xB15DD14C·0xC91EE000) + FAILED 지문
  이탈 2(0x92E6CB4C·0xB164690C) + 가드 7 전체에 자체/도너 두 변형을 실행, run·done·undec 대조.
  (본체 미변경 — 분석 하니스만.)
- **예측 (실험 전 기록):**
  - 0xB15DD14C: 자체 구성 불가 → 도너 plain 30/30 err 0, undec 0.000([사각지대] 7단계 재현), probe0 30(완주).
  - 0xCA9AA000: 자체 구성 불가 → 도너 plain ≈89/225, undec ≈0.602 재현. 단 **probe0(경계 켬)은 ≤3**
    ([사각지대] 8단계의 err 3 재현 — DQT 이상 바이트 탓, 2단계에서 보정 예정).
  - 0x95AAD000: 자체 구성 불가 → 도너 plain ≈88/46464 err 1, undec ≈0.998 재현.
  - 0xC91EE000: 자체 구성 불가 → 도너 done > 0(신규 파일, 방향성 예측만).
  - 0x92E6CB4C: 자체 plain 30/30 undec 0.000(쓰레기 채움)이지만 **probe0(자체) < 10**(경계 발동),
    probe0(도너) = 30 완주, 도너 plain undec 0.000.
  - 0xB164690C: probe0(자체) < 20(W2 실측 "run≥20 후보 전무"와 정합), 도너 plain 20/30 err 1,
    undec ≈0.259.
  - 가드: 0x92E9F48C probe0(자체) = 30 완주 > 도너, 0x9D973000 자체 900(maxW 포화) > 도너,
    0xD184A000 자체 ≫ 도너(다른 인코더 테이블은 조기 정지), 다수파 4건(0xB129B000·0xA1F57000·
    0x92E6DCCC·0xB164EC8C)은 자체 == 도너(동일 테이블이라 이식이 무연산) — **가드 7건 전부
    "자체 유지" 판정이어야 한다.**

  | 0xC91EE000 | 구성 불가 | 57 / 213/19764 err1 / 0.989 | 방향 적중(엔트로피 추가 손상 — resync 필요) |
  | 0x92E6CB4C | **0** / 30/30 err0 / 0.000(쓰레기) | **30 완주** / 30/30 / **0.000** | 적중 — probe0가 쓰레기/진짜를 가름 |
  | 0xB164690C | **0** / 30/30 / 0.000(쓰레기) | **20** / 20/30 err1 / 0.259 | 적중 |
  | 0x92E9F48C(가드) | 30 완주 / 30/30 / 0.000 | **30 완주(동률!)** / 30/30 / 0.000 | **빗나감** — 도너도 W=30 포화. 렌더 차이 mean\|diff\| 2.78·max 45·2.1% 픽셀 >16 = 도너 채택 시 CLEAN 오염 |
  | 0x9D973000(가드) | 78 / 18209/46464 / 0.608 | 78(동률) / 동일 / 동일 | **빗나감** — 렌더 완전 동일(max diff 0). "이탈" 지문이 기능적 동일 테이블(미사용 슬롯만 상이) |
  | 0xD184A000(가드) | **48** / 62/510 / 0.876 | 7 / 37/510 / 0.925 | 적중 — 자체 승 |
  | 다수파 가드 4건 | 자체=도너 완전 동일(동일 테이블) | 동률 | 적중 |

- **보강(잔여 지문 이탈 1건, 4단계 진행 중 측정):** 0xB164344C — 자체 probe0 **0**(plain 16/30
  undec 0.370 쓰레기), 도너 probe0 **24**·plain 24/30 err 2(버퍼 끝)·undec **0.102**([사각지대]
  7단계 실증치 재현). 엔진 얹어도 0.102(잔여 6 MCU < 수락 바닥 — 꼬리 한계). W2 0.963 → 0.102.
- **판단:** 지지 — 단 규칙은 "도너가 **엄격히** 우월할 때만 이식"으로 확정해야 한다(동률 → 자체
  유지). 근거: ① 0x92E9F48C에서 도너도 소형 W 포화로 동률이 나며, 채택 시 CLEAN 파일이 미묘하게
  오염된다(diff 2.78). ② probe0(경계+rate)는 plain 성공이 못 가르는 쓰레기 디코드를 갈랐다
  (0x92E6CB4C 자체 plain 30/30 undec 0.000인데 probe0 0 — 조밀 코드 공간에서 "무효 코드 없는
  디코드"는 온전성 증거가 아니라는 [레퍼런스 불변량](../reference/jpeg-entropy-coding.md) 재확인).
  ③ DQT 손상 파일(0xCA9AA000·0x95AAD000)은 이식 후에도 probe0 0~1 — **경계가 DQT 오염으로
  발동해 recover가 성과를 무효화하는 [사각지대] 8단계 구조 그대로**. DHT 이식만으로는 이 2건이
  engine에 태워지지 않는다 → 다음 사이클 = DQT 복구.

### 2단계 — DQT 복구: Y테이블 가족 매칭(도너 C) + Pq 니블 재파싱

- **가설 / 세운 이유:** 1단계에서 DQT 손상 2건이 이식 후에도 probe0 0~1(경계 오발동)로 engine
  진입이 막혔다. 0단계 관찰로 손상 형태가 다르다: ① 0xCA9AA000은 C테이블 내 소수 이상
  바이트(zigzag 7번째 78, 이웃 5~8) — **같은 인코더의 품질 세팅은 Y/C 테이블이 세트로 다니므로**,
  코퍼스에서 Y테이블이 정확히 일치하는 가족을 찾으면 그 가족의 C테이블이 원본이다. ② 0x95AAD000은
  C테이블 Pq 니블이 1(16bit)로 오파싱 — DQT 세그먼트 길이로 8/16bit를 판별해 재파싱하면 원값이
  복원된다. 나머지 이식 대상 4건(0xB15DD14C·0xC91EE000·0x92E6CB4C·0xB164690C)의 DQT는 대형 가족과
  정확 일치해 온전할 것.
- **실험:** scratchpad `w3/cycle2_dqt.py` — ① Decoder-OK 전 파일의 Y테이블(64값)→C테이블 인덱스
  구축, 대상 6건의 자체 Y/C를 정확 일치 대조(일치 가족 크기·C 차이 바이트 수·위치). ②
  0x95AAD000의 raw DQT 세그먼트 덤프, Pq=1 테이블을 seg_len 근거로 8bit 재파싱, 인덱스 대조. ③
  복구 DQT(가족 C 이식 / 재파싱)를 `make_decoder(huff=도너, qt=복구)`에 넣어 probe0·plain·undec
  재측정, 렌더 저장.
- **예측 (실험 전 기록):**
  - 0xCA9AA000: Y 정확 일치 가족 존재(확신 중간), C 차이는 1~8바이트(78 포함). 수리 후 probe0
    1 → **89 근처**(plain err1 지점까지 — 엔트로피 손상은 별개), plain done 89/undec 0.602는 불변
    (경계 off인 plain은 DQT와 무관, 렌더 색만 교정).
  - 0x95AAD000: 재파싱으로 C 8bit 복원(값 [1,1,5,3,3,2,2,3,…] 계열). Y의 이상값 134는 재파싱과
    무관하게 잔존 가능 — Y 일치 가족이 있으면(전-1 테이블) 가족 Y로 교정. 수리 후 probe0 0 → 80대.
  - 0xB15DD14C·0xC91EE000·0x92E6CB4C·0xB164690C: 자체 DQT가 대형 가족과 Y·C 모두 정확 일치(온전).
- **증거** (scratchpad `w3/cycle2_dqt.py`·`cycle2b`·`cycle2c`·`cycle2d`):
  - 이식 대상 4건 DQT 온전 확인 — Y 정확 일치 가족(98건·61건 등), C 차이 0바이트. 예측 적중.
  - **0x95AAD000 DQT 실체** (raw 세그먼트 @0xb34e, seg_len 196): Y(8bit, id0)는 전-1이 아니라
    완만한 상승 테이블 + 산재 이상치(zigzag 23:66, 35:13, 42:**0**, 44:**134**); 두 번째 테이블
    pq_tq가 **0x41(prec=4)** — 0x01의 비트 오염으로 16bit 오파싱을 유발(0단계의 "Pq=1" 추정은
    부정확, 실제 4). 8bit 재파싱 C = ~7 평탄 + 이상치(23:31, 32:71, 51:71, 55:39, 58:39). 세그먼트
    말미에 여분 64바이트(pq_tq=0xff 쓰레기) — seg_len 자체도 오염 의심. **이웃 중앙값 스무딩**
    (0 또는 3×중앙값 초과 → 중앙값)으로 Y 4곳·C 6곳 교정 → **probe0 0 → 88**(plain done 88과
    일치 — 경계 오염 해소, 엔진 진입 가능). 예측(80대) 적중.
  - **0xCA9AA000 DQT는 최대 가족의 오염본**: 최근접 (Y,C) 가족 = 273건 대가족(max 36/30)과
    Y 3 + C 9 = 12바이트 차이(C 55/64 정확 일치 — 다른 품질 세팅이면 불가능한 일치율). 가족
    테이블 통째 채택. 그러나 **probe0 1 불변 — 예측 기각.**
  - **0xCA9AA000 probe0=1의 실제 원인은 DQT가 아니라 스트림 자체**(cycle2d, 가족 DQT 적용 후):
    경계 조합 — 전부 켬 done 1 err 3 / DC만 끔 done 2 err 3 / AC만 끔 done 1 / DC+AC 끔 done 89.
    scan_start(623)부터 Y dequant DC 궤적 925→1145→1015→1090→1225→1345(상승 드리프트, MCU 5에
    q0=5 기준 한계 근접), MCU 2 Y블록 max|dequant| **25140**(AC_BOUND 6000의 4.2배). 렌더
    육안(결함 패턴): 89-MCU 영역이 채도 포화·블록 단위 무상관 노이즈 = **디싱크 쓰레기 채움**.
    [사각지대 조사] 7단계의 "이식 후 undec 0.602 복원"은 이 파일에 한해 **쓰레기 채움을 개선으로
    오측정**한 것(고주파 비반복이라는 판정 기준이 포화 무상관 쓰레기를 거르지 못함). 8단계의
    "계수 경계 quant-비례 문제" 결론도 이 파일 근거로는 성립하지 않는다 — 경계는 정당하게
    발동했다.
- **판단:** 부분 지지 — DQT 복구 2수단(가족 통째 채택·이웃 스무딩) 자체는 실효(0x95AAD000
  실증). 0xCA9AA000은 DQT 복구로 부족하고 scan_start부터의 스트림이 어긋나 있다 — 진짜 정렬
  지점이 있는지는 **엔진(resync)이 전 스트림을 스캔해 판정**하는 것이 확정적(3단계). 이식 pass의
  진위 판정을 plain undec으로 하면 안 된다는 결정적 반례 확보(기준 C의 쓰레기 채움 리스크 실증).

### 3단계 — 엔진 통합: 복구 헤더로 recover 전체 파이프라인 실행

- **가설 / 세운 이유:** 1·2단계에서 헤더 복구(DHT 이식 + DQT 교정)로 6건 전부 디코더 구성이
  가능해졌다. 이제 W2 엔진(`recover`, budget 0)을 얹으면 — 경계·probe가 살아 있으므로 —
  진짜 콘텐츠는 재동기로 수락되고 쓰레기(0xCA9AA000류)는 수락이 거부돼, 산출/비산출이 자동으로
  갈릴 것이다. [사각지대] 8단계의 "recover가 이식 성과를 무효화" 구조는 DQT 오염(0x95AAD000)의
  경우 2단계 교정으로 해소됐고, 0xCA9AA000의 경우 애초에 성과가 아니었다.
- **실험:** scratchpad `w3/cycle3_engine.py` — 6건에 `make_decoder(huff=도너, qt=교정)` 후
  본체 `rs.recover(dec, time_budget=0)`(W2 임계) 실행, undec(plain→recover)·ops·hole 기록,
  렌더 저장. 가드는 이번 사이클 제외(디코더 무변경 = 엔진 경로 동일; 전수에서 재확인).
- **예측 (실험 전 기록):**
  - 0xB15DD14C·0x92E6CB4C: probe0 30 완주였으므로 디싱크 자체가 없음 — ops 0, undec 0.000
    (CLEAN급 분류 예상).
  - 0xB164690C: MCU 20 디싱크, 잔여 10 < 수락 바닥 30 → 편집·재동기 수락 불가 → hole,
    undec_after ≈ 0.26~0.35. **수락 바닥 30보다 짧은 꼬리는 W2 규칙으로도 원천 불가** —
    초소형 한계로 기록될 것.
  - 0xCA9AA000: frontier ~1에서 전 스트림 스캔 — 진짜 정렬 지점 존재 여부 미지, 방향 예측 불가
    (이 실험이 판정). 수락 없으면 hole·전량 회색(쓰레기 비산출 = 정당).
  - 0x95AAD000: 대형(46464 MCU)·엔트로피 3.0MB — 재동기 ≥1회 수락되고 undec 0.998에서 유의미
    하강(구체 폭 미지) 예상.
  - 0xC91EE000: plain 213/19764 — 재동기 ≥1회, undec 0.989에서 하강 예상.
- **증거** (scratchpad `w3/cycle3_engine.py`, 본체 `recover` budget 0):

  | 파일 | plain(복구 헤더) | recover 후 undec | ops | 예측 대비 |
  |------|------------------|------------------|-----|-----------|
  | 0xB15DD14C | 30/30, 0.000 | **0.000** | 0 (무손상) | 적중 — CLEAN급 |
  | 0x92E6CB4C | 30/30, 0.000 | **0.000** | 0 | 적중 — CLEAN급 |
  | 0xB164690C | 20/30, 0.259 | **0.259** | 0, hole 1 | 적중 — 잔여 10 < 수락 바닥 30, 꼬리 한계 |
  | 0xCA9AA000 | 89/225, 0.602(쓰레기) | 0.996 (수락 0) | 0, hole 1 | 판정 완료 — **전 스트림 스캔에도 수락 지점 없음 = 엔트로피 자체가 손상/덮임. 쓰레기 비산출(정당 거부)** |
  | 0xC91EE000 | 213/19764, 0.989 | **0.032** | 16 (sub 9·resync 7), 21.7s | 적중 — SKIP→사실상 완전 복구 |
  | 0x95AAD000 | 88/46464, 0.998 | **0.000** | 30 (sub 22·ins 2·resync 6), 13.1s | 적중(폭은 예상 초과) — **완전 복구** |

  육안(결함 패턴): 0x95AAD000·0xC91EE000 복구 렌더는 실제 고주파 비반복 콘텐츠이며 세그먼트별
  색 캐스트·수평 밀림 밴드(기지 W4·W5 유형) 보유 — masking형·무상관 쓰레기 아님(기준 C 통과).
- **판단:** 지지 — 헤더 복구(이식+DQT 교정) 위에 W2 엔진을 얹으면 진짜/쓰레기가 자동으로 갈린다.
  ① [사각지대] 8단계의 "recover가 이식 성과를 무효화" 결론은 재분류됐다: 0xCA9AA000은 성과가
  아니라 쓰레기였고(엔진 거부가 정당), 0x95AAD000은 DQT 교정 후 엔진이 완전 복구했다. ②
  분류·저장 정책 결정 필요: 헤더 복구 파일은 원본이 디코드 불가라 "FAILED = 원본 보존" 논리가
  성립하지 않음(0xB164690C: 복구 렌더 0.259가 유일한 산출 후보). 이식 시 헤더 복구 파일의 저장
  기준(undec_after 임계 + probe 검증 디코드 영역)을 정한다. 다음: FIELD·SOS·SOF 축(사이클 4).

### 4단계 — FIELD·SOS·SOF(부분) 재구성: 정형 템플릿 + 관용 세그먼트 스캔 + probe 대결

- **가설 / 세운 이유:** 샘플 8건의 헤더 바이트 검사(scratchpad `w3/inspect_sos_sof.py`)에서 손상이
  정형화됐다 — ① 단일 바이트 비트 플립(qid 0x01→0x41(65)·comp id 0x01→0x81(129)/0x09(9)·샘플링
  니블 0, 마커 바이트 FFDB→FF4B), ② 세그먼트 길이/ns 바이트 오염(워크 탈선 — 실제 SOS는 생존:
  0x92EBE2CC의 FFDA@0x661 완전 정형 14바이트), ③ 이중 헤더(0x92E6980C: DQT·SOF·DHT 클러스터
  2벌 + SOS 1개), ④ APP1 내 EXIF 썸네일 헤더가 주 헤더와 혼동됨(0xCF6E8000·0xBE671000 등 —
  첫 FFC0/FFDA는 썸네일 것). 카메라 헤더는 고도로 정형(SOF len 17·prec 8·ncomp 3, SOS len 12·
  ids (1,2,3)·(0,0)(1,1)(1,1), 대형 2816×2112=2×1·2592×1944=2×2, qids (0,1,1))이므로 **관용
  스캔(마커·길이 오염 허용, 패턴 `00 11 08`·`FF DA 00 0C 03` 등)으로 후보 세그먼트를 모으고,
  필드는 템플릿으로 교정하고, 남는 자유도(SOS 위치·샘플링·치수·이중 클러스터)는 probe0 대결로
  고르면** FIELD·SOS군이 복구된다.
- **실험:** scratchpad `w3/cycle4_reconstruct.py` — 후보 열거(SOS 후보 × SOF 후보 × 샘플링 후보
  × DHT 자체/도너) 상한 ~24조합, 각각 `make_decoder` 후 probe0 채점, 최고 후보로 plain +
  `recover`(budget 0) 실행. 대상: FIELD 4(0x17544000·0x42D26000·0xBE671000·0x99EDA000),
  SOS 2(0x92EBE2CC·0xCF6E8000), 마커 오염 DEAD 1(0xCE2C4000), 이중 헤더 1(0x92E6980C).
- **예측 (실험 전 기록):**
  - 0x92EBE2CC: 생존 SOS(0x661)+도너 DHT 채움 → 30/30, undec 0.000 (CLEAN급).
  - 0x17544000: 템플릿 comps(ids 1,2,3·qids 0,1,1)+샘플링 2×1 채택 → 디코드 진행. 파일 1.0MB는
    대형 원본(통상 ~3MB) 대비 절단 의심 — done 대략 1/3 수준, 부분 복구(undec ~0.6대) 방향.

    오염으로 존재** 예측 — 갭에서 `00 11 08` 패턴 발견, 치수 획득, DQT는 FF4B@0x34ef 내용

- **판단:** 부분 지지 — 재구성 기계(관용 스캔+템플릿+대결)는 실효(8건 중 5건 완전/부분 복구,
  전부 fit·probe 검증). 단 선택 규칙에 **치수 내림차순 그룹 우선**(주 이미지 그룹의 best가
  바닥(min(30,(총+1)//2)) 통과 시 채택, 미달 시 다음 그룹으로 강하 — 썸네일은 주 이미지 사망
  시의 구제 산출)이 필요하다. 다음 사이클(4b)에서 수정 재실험.

### 4b단계 — 치수 그룹 우선 선택으로 썸네일 가림 해소

- **가설 / 세운 이유:** 4단계에서 probe run 최대 규칙이 썸네일(총 MCU 캡 포화)을 주 이미지보다
  우선시켰다. 후보 변형을 치수 픽셀 수 내림차순 그룹으로 나눠 **큰 그룹부터 바닥 통과 시 즉시
  채택**하면, 주 이미지가 살아 있는 파일은 주 이미지를, 주 이미지 개구부가 죽은 파일만 썸네일을
  산출한다.
- **실험:** `cycle4b` — 그룹 우선 선택으로 8건 재실행(이전 4건 승자 불변 확인 포함), 대형 4건은
  엔진(budget 0)까지.
- **예측 (실험 전 기록):**
  - 0x17544000·0x42D26000(1.0MB — 원본 ~3MB 대비 절단 의심): 주 그룹 채택(probe0 ≥30 예상),
    엔진 후 부분 복구(undec 대략 0.5~0.8 방향). 절단이라 fit=0.
  - 0x99EDA000(2.8MB): 주 그룹 채택, 상당 복구(undec < 0.3 방향). 치수 2240 vs 2112는 decode-fit
    신호로 판정될 것(확신 낮음 — done이 46464 부근이면 2112 지지).
  - 0xBE671000(8.7MB, 오버런 포함): 주 그룹 채택, 완주 근접(undec < 0.1 방향).
  - 이전 완전 복구 4건 + 0xCF6E8000: 승자·수치 불변(그룹이 하나뿐이거나 주 그룹이 이미 승자).
- **증거** (scratchpad `w3/cycle4b_groupsel.py`):
  - **0x99EDA000 주 이미지 근완전 복구**: 주 그룹(2816×**2240**) probe0 239 → recover **undec 0.034**
    (ops 19: sub 14·ins 1·resync 4). 예측(2112 선택) 빗나감 — 아래 4d의 EOI 앵커로 **2240이
    진짜 높이로 판정**(파일 끝 0x2a8333에 EOI 정확 위치 + undec 0.034 < 2112-절단 가정 하한 0.057).
    "2816×2240은 코퍼스 미관측 해상도 = 손상"이라는 0단계 추정은 기각 — **코퍼스 prior를 치수
    후보의 기각 근거로 쓰면 안 된다**(순위 힌트로만).
  - **주 사망 → 썸네일 구제 강하 2건**: 0x42D26000(주 best 19 < 바닥 30), 0xBE671000(주 best 0)
    → 320×240 EXIF 썸(600/600, undec 0.000) 채택. 렌더 육안: 실콘텐츠.
  - **잔여 문제**: 0x17544000 — 주 개구부 probe0 36이 바닥(30)을 통과했으나 엔진 후 undec
    **0.998**(플레인 done 134/46464) = 빈 렌더가 완벽한 썸네일을 가림. **그룹 강하를 probe
    바닥만이 아니라 엔진 결과(undec ≥ 0.95면 강하)로도 구동해야 한다.**
  - 소형 4건·0xCF6E8000 승자·수치 불변 ✓.
- **판단:** 그룹 우선 대체로 지지. 두 규칙 추가 필요 — ① 엔진 결과 기반 강하(undec ≥ 0.95),
  ② 소형 쓰레기(0xCE2C4000) 거부 장치. ②의 후보로 렌더 통계·썸 상관을 4c·4d에서 측정.

### 4c·4d단계 — 쓰레기 게이트 후보 3종 측정: 렌더 통계 2종 기각, EOI-관통 게이트 채택

- **가설 / 세운 이유:** 0xCE2C4000의 재구성(120×160, probe 80/80 포화·fit 정확·undec 0.000)이
  기준 C 육안에서 **블록 단위 무상관 체커보드 = 쓰레기**로 판명(자동 게이트 전부 통과한 유일
  반례). 소형 이미지는 W 캡이 작아 probe의 반쓰레기 판별력이 약하다. 거부 장치 후보: (a) 크로마
  수평 그래디언트(쓰레기는 채도 폭주), (b) 평활 블록 비율(실사진은 평탄 영역 보유), (c) EXIF
  썸네일 교차 상관.
- **실험:** scratchpad `w3/cycle4c_content_gate.py`·`cycle4c2_smooth.py`·`cycle4d_thumbcorr.py` —
  게이트 도달 가능(probe 통과) 표본: 진짜 13종(cycle3·4 복구본, CLEAN 가드, W2 recovered 3) vs
  쓰레기 1종(0xCE2C4000) + 참고 쓰레기(probe에서 이미 차단되는 0xCA9AA000 등).
- **증거 — (a)·(b) 기각:**
  - c_grad: 진짜 1.01~6.75 vs 쓰레기 13.85로 갈리는 듯했으나 **진짜 0xCF6E8000이 19.02**(밀림
    밴드·캐스트의 부분 복구) — 역전.
  - smooth%: 쓰레기 0.153인데 **진짜 0x92EBE2CC 0.157·0x92E6CB4C 0.148·0xCF6E8000 0.031** — 분리 불가.
  - 교훈: **심하게 밴드·캐스트된 진짜 부분 복구와 소형 고텍스처 진짜는 렌더 통계로 쓰레기와
    구분되지 않는다** — W4(밀림)·W5(캐스트) 보정 전에는 렌더 통계 게이트를 시도하지 말 것.
- **증거 — (c) 기각:** ycorr(주 렌더↓ vs 썸): 진짜 0x99EDA000 **0.177**, 진짜 0x95AAD000
  **−0.04**(완전 복구인데도 — 세그먼트 수평 밀림이 픽셀 정렬을 파괴), 쓰레기 0.19 — 역전.
  교훈: **W4 밀림 존재 하에서 픽셀 공간 상관은 인증 신호가 못 된다.**
- **증거 — 구조 신호 확정(자기 정정 1회 포함):** ① 최초에 "0xCE2C4000 엔트로피 +224B에
  FFD9(EOI 관통)"로 판단했으나 이는 **0x99EDA000의 FFD9 목록을 혼동한 오독** — 실측(0xCE2C4000
  자체)의 FFD9는 0x3336(APP1 말미 = 썸 EOI)과 0x1a652(파일 끝 = 주 엔트로피 완결)뿐. ② 주
  SOS(0x3583~) 엔트로피는 94KB인데 채택된 120×160 해석은 **4,538바이트(4.8%)만 소비**(453
  bits/MCU — 레이트는 정상) = 치수 과소 해석. ③ 거대 그리드 D-프로브: 도너 DHT+s22로 전량
  소비 시 D=1221 — 640×480(1200 MCU) 재해석 → plain 1200/1200 fit=1 undec 0.000이지만 **렌더
  여전히 블록 체커보드 쓰레기 + probe0 116 ≪ W 900**(온전 스트림이면 개구부에서 경계가 발동할
  이유가 없음). 자체 DHT는 D=673에서 err 1 = 자체 DHT도 손상 → **이 파일의 참 테이블은 확보
  불가(도너 부적합 + 자체 손상)** — 정답은 주 이미지 SKIP + 썸 구제.
  ④ 반면 진짜 fit==1 채택들은 전부 probe0 == W 포화(0x92EBE2CC 30/30, 0x92E6980C 36/36, 썸
  600/600)이고 소비율도 정상(썸: 엔트로피 구간을 "scan_start→그 뒤 첫 FFD9"로 재정의하면
  10.1KB/11.9KB = 0.85; 주 SOS 기준 분모(파일 끝 EOI)로는 0.096으로 오기각되므로 **분모는 반드시
  '그 SOS 뒤 첫 FFD9'**).
- **판단:** 렌더 통계·상관 게이트 폐기. **fit==1 채택 조건 = probe0 == min(900,total) 포화 AND
  소비율 ≥ 0.5(분모: scan_start→첫 FFD9, 없으면 EOF)**, fit==0 채택 조건 = 엔진 undec_after <
  0.95. 이 두 구조 게이트가 0xCE2C4000의 두 쓰레기 해석(120×160 소비 4.8% ✗, 640×480 probe 116
  ✗)을 모두 기각하고 진짜 썸(포화+0.85)만 통과시킨다. D-프로브 치수 추론은 실효 사례가 없어
  이식 범위에서 제외(미래 레버로 기록). 최종 알고리즘(v4): ① 트리거 = Decoder 실패 또는
  probe0(자체) < 바닥(min(30,(총+1)//2)), ② 후보 열거(관용 스캔+템플릿), ③ 치수 px 내림차순
  그룹별 — probe 바닥 → fit==1이면 포화+소비율 게이트 → 엔진 → undec<0.95 → 채택(RECOVERED +
  header_fix), 실패 시 다음 그룹 강하(썸 구제), ④ 전 그룹 실패 → SKIP 유지, ⑤ 자체 구성 가능
  파일은 자체보다 엄격 우월시만 대체.

### 4e단계 — 최종 알고리즘(v4) 전 샘플 검증

- **가설 / 세운 이유:** 1~4d의 규칙을 하나로 합친 v4(트리거 → 후보 열거 → px 그룹 강하 —
  후보별 게이트: probe 바닥 / fit==1이면 포화+소비율≥0.25 / 엔진 undec<0.95)가 실패 샘플 14건
  전부에서 "진짜만 산출, 쓰레기·불능은 SKIP"을 달성할 것. 소비율 임계는 0.25로 — 관측 쓰레기
  (0.048)와 관측 진짜 최저(~0.45 추정, carve 오버런 꼬리 포함 파일)의 사이(로그 중앙).
- **실험:** scratchpad `w3/cycle4e_final.py` — 14건 전체 + 가드 7건 트리거 검사.
- **예측 (실험 전 기록):**
  - 최종 산출(undec): 0x95AAD000 **0.000**(DHT+DQT 스무딩), 0xC91EE000 **0.032**, 0xB15DD14C
    **0.000**, 0x92E6CB4C **0.000**, 0xB164344C **0.102**, 0xB164690C **0.259**, 0x92EBE2CC
    **0.000**, 0x92E6980C **0.000**(96×96), 0x99EDA000 **0.034**(2816×2240), 0xCF6E8000
    **0.625**, 0x17544000 **썸 320×240 0.000**(주 엔진 0.998 강하), 0x42D26000 **썸 0.000**

    후보 전부 쓰레기 문맥 — 비 JPEG 의심, 전 후보 바닥 미달 예상), 0xCE2C4000의 주 SOS 해석

- **증거 (1차 실행 + 결함 3건 발견·수정, v4→v4.2):**
  - 1차 실행 적중: 가드 7/7 비발동, 0x95AAD000 **0.000**(자동 재구성이 수동 사이클 2·3 결과 재현,
    ops 34), 0xC91EE000 0.032, 0xB15DD14C·0x92E6CB4C·0x92EBE2CC·0x92E6980C 0.000, 0xB164344C
    0.102, 0x99EDA000 0.034, 0xCF6E8000 0.625, 0x17544000 주 기각(0.998)→썸 채택, 0x42D26000·
    0xBE671000 썸 구제, 0xCA9AA000·0x2F738BE8 SKIP.
  - **결함 1 — DHT 중복 제거가 counts만 비교**: 0xB164690C(심볼 바이트만 손상 — counts는 도너와
    동일)의 도너 후보가 중복으로 제거돼 재구성 실패. symbols 포함 비교로 수정.

    채택돼 색이 물 빠짐(undec 0.011). 동률 run 후보를 plain (fit, undec)로 정렬해 해소(수정 후

## 기각된 가설 / 막다른 길

- **"도너 DHT는 DQT 가족별 매칭 필요"(백로그 W3 전제) → 기각(0단계).** Decoder-OK 696건 교차에서
  가족 178종 전부 동일 DHT(050df0dc, Annex-K) — 가족별 차이 없음. 교훈: **코퍼스 상수(공유 테이블)는
  가정하지 말고 전수 교차표로 확인하라** — 매칭 로직을 먼저 설계했으면 불필요한 복잡도가 됐다.
- **"계수 경계가 quant-비례하지 않아 대형 DQT 파일에서 오발동"([사각지대] 8단계) → 이 파일 근거로는
  기각(2단계).** 0xCA9AA000의 경계 발동은 DQT 이상이 아니라 scan_start부터 어긋난 스트림에 대한
  정당 발동이었다(가족 DQT 교정 후에도 probe0 1, Y DC 상승 드리프트 925→1345, MCU 2 AC 25140).
  교훈: **경계 오발동을 의심하기 전에 그 스트림이 온전한지를 먼저 검증하라** — plain 디코드
  성공(undec 하락)은 온전성 증거가 아니다.
- **"이식 후 plain undec 하락 = 복원"([사각지대] 7단계의 0xCA9AA000 0.602) → 기각(2단계).**
  렌더 육안·DC 궤적으로 쓰레기 채움 판명. 교훈: **헤더 교체 실험의 진위는 undec이 아니라
  probe(경계+rate)와 육안으로 판정하라** — undec은 회색만 재므로 쓰레기 채움에 속는다.
- **렌더 통계 게이트 2종(크로마 그래디언트·평활 블록 비율) → 기각(4c).** 심하게 밴드·캐스트된
  진짜 부분 복구(0xCF6E8000 c_grad 19.02, smooth 0.031)가 쓰레기(13.85, 0.153)와 역전. 교훈:
  **W4(밀림)·W5(캐스트) 보정 전에는 복구 렌더에 통계 게이트를 시도하지 말 것.**
- **EXIF 썸네일 픽셀 상관 게이트 → 기각(4d).** 완전 복구본(0x95AAD000)조차 corr −0.04 — 세그먼트
  수평 밀림이 픽셀 정렬을 파괴. 교훈: **W4 밀림 존재 하에 픽셀 공간 상관은 인증 신호가 못 된다.**
- **"0xCE2C4000 엔트로피 +224B에 EOI(관통 게이트 근거)" → 자기 정정(4d).** 0x99EDA000의 FFD9
  목록을 혼동한 오독 — 실제로는 파일 끝 EOI. 교훈: **파일별 원시 측정값을 교차 인용할 때는 파일명을
  같이 기록하고 재확인하라** — 다파일 병렬 분석에서 목록 혼동은 그럴듯한 오결론을 만든다.
- **레이트 사전 게이트(엔트로피/총MCU ≤ 3000) → 기각(4e).** EOI 소실 오버런 carve(0xCF6E8000)의
  분모 오염으로 진짜 기각. 교훈: **carve 산출물에서 '엔트로피 길이' 절대 게이트는 EOI 부재 파일에서
  신뢰 불가** — 길이 신호는 완결을 주장하는 결과에만 조건부로 써라.
- **fit==1 probe 포화 요구 → 기각(4e).** 진짜-경미손상 썸(0xCE2C4000, probe 31/80·소비율 0.856)
  오기각. 관측 사례에서 쓰레기/진짜를 가른 것은 포화가 아니라 소비율(0.048 vs 0.45~1.0).
- **동률군 tier 제한(최상 run만 평가) → 기각(v4.2 회귀 2).** 하위 tier의 진짜 후보(썸)가 평가
  대상에서 제외. tier 루프(상위 전멸 시 하위 진행)로 수정. 교훈: **순위 컷은 "평가 순서"로만 쓰고
  "평가 자격"으로 쓰지 마라** — 게이트가 상위를 기각할 수 있는 체계에서는 하위가 정답일 수 있다.
- **코퍼스 prior로 비관측 해상도(2816×2240) 기각 → 기각(4b·4d).** EOI 앵커(파일 끝 정확 위치)와
  undec 0.034(<2112-절단 가정 하한 0.057)로 2240이 진짜 판명. 교훈: **코퍼스 분포는 치수 후보의
  순위 힌트로만 쓰고 기각 근거로 쓰지 마라.**
- **D-프로브 치수 추론(거대 그리드 총 MCU 수 → 코퍼스 매칭) → 보류(4d).** 유일 후보 사례
  (0xCE2C4000 640×480)가 쓰레기로 판명돼 실효 사례 0 — 이식 범위에서 제외, 미래 레버로 기록.

1. **트리거**: `Decoder(data)` 구성 실패 **또는** probe0(자체, 경계+rate) < 바닥

   fit==1이면 소비율 0.25~1.1(분모 scan_start→첫 FFD9), 엔진(budget 0) undec < 0.95,

   0x92E6980C 0.000·0xCF6E8000 0.625·0x17544000 0.000(썸)·0xBE671000 0.000(썸)·0xCE2C4000
