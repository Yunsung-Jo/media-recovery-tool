# recover.py 동작 계약

이 문서는 현재 `recover.py`의 사용자 관점 동작과 복구 엔진의 유지해야 할 불변 조건을 설명한다.
설계 선택의 근거는 관련 ADR, 최신 기준선과 남은 작업은 [현재 상태](../current-state.md)를 본다.

## 개요

`carve.py`가 추출한 손상 JPEG를 비트 단위 디코더, 바이트 편집, 재동기, 헤더 재구성으로 복구한다.
복구할 근거가 없는 영역은 생성하지 않고 회색으로 남기며, 파일별 결과와 지표를 `report.csv`에 기록한다.
복구 엔진은 3컴포넌트 baseline JPEG를 대상으로 한다.

## 인터페이스

| 이름 | 설명 | 타입 | 기본값 |
|---|---|---|---|
| `input` | 입력 디렉터리 | positional | — |
| `-o, --output` | 출력 디렉터리 | str | 입력 디렉터리 옆의 `<이름>_recovered` |
| `-q, --quality` | 재인코딩 복구본의 JPEG 품질 | int | `95` |
| `-j, --jobs` | 병렬 프로세스 수 (`0`=CPU 수, `1`=순차) | int | `0` |
| `--fast` | 가까운 재동기 위치만 찾는 빠른 모드 | flag | 철저 모드 |
| `--time-budget` | `recover()` 호출 1회당 탐색 시간 상한(초, `0`=무제한) | float | 철저 90 / fast 20 |

입력은 최상위의 소문자 확장자 `*.jpg`만 수집한다. 하위 디렉터리, `*.jpeg`, 대문자 확장자는 처리하지
않는다. 철저 모드는 가까운 300,000비트를 먼저 찾고 필요하면 남은 스트림을 거칠게 훑는다. 빠른 모드는
가까운 160,000비트만 찾는다.

시간 상한은 파일 전체가 아니라 개별 `recover()` 호출에 적용된다. 헤더 재구성은 여러 후보마다
`recover()`를 호출할 수 있어 한 파일의 실제 경과 시간이 상한보다 길 수 있다. 비교 실험과 기준선
재계산에는 `--time-budget 0`을 사용한다([ADR 0003](../adr/0003-recover-perf-optimization.md)).

## 출력과 분류

실행을 시작하면 아래 여섯 서브디렉터리를 만든다. 분류 결과가 없어도 디렉터리는 존재한다.

| action | 저장 위치 | 저장물과 판정 |
|---|---|---|
| `RECOVERED` | `recovered/` | 바이트 편집 또는 재동기를 적용한 재인코딩본 |
| `HEADER_RECOVERED` | `header_recovered/` | 구조 게이트를 통과한 헤더 재구성·복구 재인코딩본 |
| `CLEAN` | `clean/` | 편집·재동기 0회이고 복구 전 회색 비율이 2% 미만인 원본 바이트 |
| `FAILED` | `failed/` | 편집·재동기 없이 hole에서 멈춘 파일의 원본 바이트 |
| `SKIP_UNDECODABLE` | `skip_undecodable/` | 디코더 구성과 헤더 재구성이 모두 실패한 원본 바이트 |
| `ERROR` | `error/` | 워커 예외가 발생한 원본 바이트. 복사 자체가 실패할 수 있으며 오류는 콘솔에 표시한다 |

`CLEAN`과 `FAILED`는 열화된 재인코딩본 대신 입력을 보존한다. `HEADER_RECOVERED`는 입력을 정상 디코드할
수 없으므로 재구성한 렌더가 유일한 산출물이다. 저장 파일명은 입력 stem에 `.jpg`를 붙인다.

`report.csv`는 출력 루트에 생성되고 입력 파일마다 한 행을 기록한다.

| 컬럼 | 의미 |
|---|---|
| `filename`, `action` | 입력 파일명과 위 여섯 분류 |
| `gray_before`, `gray_after` | 평탄하고 무채색인 픽셀 비율 |
| `undec_before`, `undec_after` | RGB 128 부근의 실제 미복구 회색 비율 |
| `undec_delta`, `worse` | after-before, 그리고 0.01 초과 악화 표시 |
| `recover_sec` | 정상 복구 또는 헤더 재구성 경로의 경과 시간 |
| `ops` | 적용한 치환·삭제·삽입·재동기의 합 |
| `sub`, `del`, `ins`, `resync`, `hole` | 복구 연산별 횟수 |
| `mcus`, `image_size` | MCU 수와 해상도 |
| `shifted` | 최종 보정에서 절대 오프셋이 0이 아니거나 의도적으로 폐기된 복구 밴드 수. 직전 오프셋을 상속한 밴드도 포함 |
| `mcu_ins` | 디코드 frontier의 원래 유효 위치 중 보정 뒤 소유 MCU가 없어 RGB 128로 남은 슬롯 수 |
| `mcu_drop` | 캔버스 밖 클리핑·밴드 겹침·짧은 밴드 폐기로 최종 출력에 남지 않은 디코드 원본 MCU 수 |
| `shift_margin` | 최종 비영 배치에 대응하는 신뢰 local 추정과 채택 signature 관계의 최소 margin. 없으면 0 |
| `shift_reject` | 정밀 배치가 안전 게이트에서 기각되고 재동기 경계 후퇴도 보정을 적용하지 못했으면 1, 아니면 빈 값 |
| `spatial_changed` | 절단 밴드, 전역 행, 구조적 국소 또는 legacy 행 보정 중 하나라도 최종 RGB를 바꿨으면 1 |
| `row_global_passes` | 최종 선택한 절대 행 위상까지 진행한 전역 연쇄 패스 수 |
| `row_global_changes` | 최종 절대 행 위상에서 이전 행과 위상이 달라지는 경계 수 |
| `row_local_cuts` | 전역 해가 없을 때 구조적 국소 보정이 채택한 절단점 수 |
| `header_fix` | 교체한 `dht`, `dqt`, `sof`, `sos` 조합 |

`SKIP_UNDECODABLE`과 `ERROR`는 복구 지표가 빈 값이다. 실행 종료 시 action별 건수, 복구 전후 평균,
악화 건수, MCU 대역별 지표와 헤더 복구 조합을 콘솔에 요약한다. `spatial_changed`나 안전 기각이 있으면
적용 파일·절단 밴드 수, `mcu_ins`, `mcu_drop`, 기각 파일 수도 출력한다. 따라서 절단 밴드 수가 0인
global-only 보정도 적용 파일 수에서 빠지지 않는다. `ins`와 `del`은 엔트로피 비트스트림의
바이트 연산이고 `mcu_ins`와 `mcu_drop`은 최종 공간 재배치 통계다. `ops`에는 MCU 재배치를 포함하지 않는다.
`gray_after`, `undec_after`, `worse`, `recover_sec`는 최종 공간 보정까지 반영한다.

## 처리 흐름

1. 입력 디렉터리의 `*.jpg`를 이름순으로 수집한다.
2. `carver/jpegdecode.py::Decoder`로 헤더와 엔트로피 스트림을 구성한다.
3. 구성이 실패하면 헤더 재구성을 시도하고, 성공하면 `HEADER_RECOVERED`, 실패하면
   `SKIP_UNDECODABLE`로 끝낸다.
4. 구성이 되면 일반 복구를 실행한다. 첫 MCU부터 clean run이 짧아 헤더 손상이 의심되는 파일은 헤더
   재구성 결과도 계산하고, 보정 전 일반 경로보다 미복구 비율이 0.01 초과 개선될 때만 대체한다.
5. 선택된 일반 또는 헤더 복구 렌더에 MCU 행 위상 보정을 정확히 한 번 적용한다.
6. 일반 경로는 복구 연산과 회색 비율에 따라 `CLEAN`, `FAILED`, `RECOVERED` 중 하나로 분류한다. 엔트로피
   연산이 0이어도 `spatial_changed=1`이면 보정 RGB를 `RECOVERED`로 저장한다.
7. 모든 결과를 `report.csv`에 기록한다.

## 엔트로피 복구 계약

### 디싱크 탐지

디코더는 MCU를 순서대로 처리하며 무효 Huffman 코드, dequant 계수 상한 초과(DC 1400, AC 6000),
MCU당 평균의 4배를 넘는 비트 소비를 만나면 정지한다. 이 위치와 직전 DC 예측값이 복구 탐색의
출발점이다([ADR 0001](../adr/0001-resync-recovery.md)).

### 바이트 편집과 재동기

각 정지점에서 다음 순서로 시도한다.

1. 정지점 부근의 한 바이트를 치환·삭제·삽입하고, 이후 clean run이 가장 길어지는 편집을 찾는다.
2. 편집이 충분히 개선되지 않으면 이후 비트 위치를 탐색해 손상 구간을 건너뛴다.
3. 각 재개 위치에서 직전 DC 캐리와 Y·Cb·Cr 전체 0 리셋을 모두 평가해 clean run이 긴 쪽을 쓴다.
4. 어떤 후보도 수락 기준을 통과하지 못하면 `hole`을 기록하고 이후 영역을 회색으로 둔다.

남은 MCU를 `rem`, probe 창을 `W=min(900, rem)`이라 할 때 주요 수락 조건은 다음과 같다.

- 바이트 편집: `run > base + min(30, rem//4)`이면서 `run > min(120, max(20, 0.4·rem))`
- 재동기: `run >= max(30, 0.35·W)`
- 버퍼 끝까지 이어진 재동기 후보: `run >= 30`
- 원래 지점에서 24비트 미만 떨어진 DC=0 재개는 masking으로 보고 거부

임계의 근거와 DC 물리 범위를 수락 필터로 쓰지 않는 이유는
[ADR 0005](../adr/0005-scaled-accept-threshold.md)에 있다.

### 세그먼트 불변 조건

복구 상태는 `(시작 MCU, 시작 비트, DC 예측값)` 세그먼트 목록으로 유지한다. 처리는 항상 작은 MCU에서
큰 MCU 방향으로 진행하고, 새 세그먼트는 이전 세그먼트보다 뒤의 비트에서 시작해야 한다. 이미 확정한
앞부분을 다시 디코드해 반복 콘텐츠를 만드는 동작은 허용하지 않는다.

### MCU 행 위상 보정

엔트로피 복구와 헤더 후보 선택을 끝낸 뒤 최종 디코드 frontier 안의 복구 밴드를 MCU 단위로 재배치한다
([ADR 0011](../adr/0011-resync-segment-mcu-alignment.md)). 밴드 경계는 수락한 `sub`·`del`·`ins`와
`resync`의 실패 MCU를 모두 사용한다. 정밀 경계가 불안전하면 실제 재동기 시작점만 사용한 coarse 배치로
한 번 후퇴한다. 명시적인 `phase_cuts=[]`는 수락된 편집·재동기 근거가 없다는 뜻이므로 픽셀 신호만으로
공간 이동을 만들지 않는다.

1차 밴드 배치는 MCU 열별 좌우 녹색 경계의 DC 제거 잔차, 수직 그래디언트 비상관도, 절대 경계 차와
전체 폭 경계 profile 상관을 함께 사용한다. 짧은 내부 밴드는 제한된 예산 안에서 폐기할 수 있지만, 비영
이동 없이 폐기만 하는 결과는 적용하지 않는다. 첫 밴드는 MCU 0의 `resync` phase cut과 MCU 0의 비영
시작 비트 세그먼트가 모두 있을 때만 이동할 수 있다.

1차 배치 뒤에는 source JPEG의 실제 샘플링으로 계산한 모든 MCU 행 경계에 전역 절대 위상 보정을 먼저
시도한다.

- 첫 패스는 경계 위아래 1·2·3·4픽셀 strip이 고른 최적 위상이 원형 거리 2 MCU 안에서 모두 일치하고,
  대표 위상의 절댓값이 4 MCU 이상일 때만 사건을 만든다. 각 strip은 support 64 이상, score 0.14 이상,
  0위상 대비 gain 0.08 이상, 비인접 후보 대비 margin 0.055 이상이어야 한다.
- 최상단 행의 절대 위상은 0으로 고정하고 각 사건의 상대 위상을 아래 행들에 누적한다. 같은 위상인 연속
  행은 flat scan span 하나와 동등하며, 행 안의 조각을 반대편으로 순환시키지 않는다.
- 첫 배치로 드러난 연쇄는 네 strip 중 셋의 lower-quartile 합의를 사용해 최대 5패스 탐색한다. 이때
  score 0.10, gain 0.055, margin 0.025를 요구한다. 각 후보는 직전 출력이 아니라 같은 1차 RGB와 최초
  owner map에서 누적 절대 위상을 한 번만 렌더한다.
- 각 탐색 패스는 잔차 합을 직전의 85% 이하로 줄이고 source-owner의 유일·단조 조건과 손실 예산을 지켜야
  한다. 중간 패스가 독립 감사에서 일시적으로 안전하지 않아도 탐색은 계속하지만, 반환 후보는 시작 상태와
  이전 안전 후보에 대해 exact·soft·multistrip 회귀가 없어야 한다. 후보 순위는 exact, multistrip, soft,
  relaxed 잔차를 먼저 비교하고 그 다음 MCU 손실을 비교한다.

전역 후보가 채택되면 같은 경계를 재해석하지 않도록 이후 국소 단계를 생략한다. 전역 사건이 없거나 끝까지
안전 후보가 없으면 편집 절단점 주변의 구조적 짧은 구간 보정을 적용하고, 그 뒤 기존 보수적 행 스티치로
남은 밀림을 한 번 더 검사한다.

모든 단계에서 `max(mcu_ins, mcu_drop)`은 `ceil(전체 MCU·0.05)`를 넘을 수 없다. 출력 크기는 바꾸지 않고
원본 MCU를 역순으로 놓거나 복제하지 않는다. 양의 간격은 RGB 128 MCU로 남기고 겹침에서는 뒤 밴드가 앞
밴드의 경계 쪽 MCU를 대체한다. 부분 가장자리 MCU는 전체 디코드 계수 픽셀을 옮긴 뒤 원래 해상도로 자른다.
밀림 제거가 우선이므로 이 한도 안의 유효 MCU 유실과 `undec_after` 증가는 허용한다.

## 헤더 복구 계약

헤더 복구는 마커와 길이가 일부 손상돼도 SOS·SOF·DQT·DHT 후보를 찾고 다음 재료를 조합한다.

- SOS 정형 body와 SOF의 8비트·3컴포넌트 구조
- 파일 자체에서 복구한 DQT와 이웃 중앙값 스무딩 후보
- 파일 자체 DHT와 ITU-T T.81 Annex-K 전형 4테이블 도너
- 자체 치수와 제한된 샘플링 후보

후보는 다음 구조 게이트를 통과해야 한다([ADR 0006](../adr/0006-header-recovery-structural-gates.md)).

- 시작 clean run이 `min(30, (총 MCU+1)//2)` 이상
- 전 MCU를 디코드한 후보의 엔트로피 소비율이 0.25~1.1
- 복구 후 `undec_after < 0.95`
- 자체 헤더로 일반 경로가 가능한 파일은 그 결과보다 `undec_after`가 0.01 초과 개선

렌더 통계, 썸네일 픽셀 상관, 코퍼스 해상도 빈도는 후보 기각 필터로 사용하지 않는다.
이 구조 게이트와 자체 헤더 우월 비교는 보정 전 렌더로 수행하고, 선택된 경로에만 MCU 공간 보정을 한 번
적용한다.

## 알려진 한계

- 짧거나 경계 신호가 모호한 밴드, 안전 게이트가 기각한 후보에는 수평 밀림이 남을 수 있다.
- MCU 0의 실제 재동기 절단과 비영 시작 비트가 함께 없으면 최상단 복구 밴드를 이동하지 않으므로, 이
  메타데이터 없이 최상단 자체가 밀린 예외에는 보정이 남을 수 있다.
- `phase_cuts=[]`인 파일은 정상 이미지의 자연 경계를 오인하지 않도록 공간 보정을 생략한다.
- 픽셀만으로 실제 행 경계와 완전히 같은 통계를 갖는 자연 세로 경계는 원리상 확정 구분할 수 없다.
- DC=0 재개는 세그먼트별 색 캐스트를 만들 수 있다.
- 물리적으로 소실됐거나 입력 버퍼가 끝난 영역은 회색으로 남는다.
- progressive, 비 3컴포넌트 JPEG와 재구성 재료가 부족한 헤더는 복구 대상이 아니다.

후속 작업과 우선순위는 [현재 상태](../current-state.md)에만 유지한다.

## 엣지 케이스

| 상황 | 동작 |
|---|---|
| 입력 디렉터리가 없음 | 오류를 stderr에 출력하고 exit code 1 |
| 입력 디렉터리에 `*.jpg`가 없음 | 여섯 출력 폴더를 만든 뒤 메시지를 출력하고 종료. `report.csv`는 만들지 않음 |
| 복구 후보가 진위 기준을 통과하지 못함 | 원본을 `FAILED` 또는 `SKIP_UNDECODABLE`로 보존 |
| 워커 예외 | 가능한 경우 원본을 `error/`에 복사하고 `ERROR` 행 기록 |

## 사용하는 모듈

- `carver/jpegdecode.py` — baseline JPEG 헤더·엔트로피 디코더
- `carver/resync.py` — 바이트 편집, 재동기, 분류와 저장
- `carver/headerfix.py` — 헤더 후보 재구성과 구조 게이트
- [포맷 메모](../format-notes.md) — 구현이 전제하는 JPEG 사실
