# recover.py

- **날짜:** 2026-07-03 (최초 2026-06-03; 이번 갱신은 수락 임계 잔여 비례화·데이터-끝 완주 수락 반영)
- **상태:** Accepted

---

## 개요

`carve.py`가 추출한 손상 JPEG를 **resync 엔진**으로 복구하는 도구.
바이트 단위로 디싱크(비트 정렬 어긋남) 지점을 짚어 정렬을 복원하고,
복구 가능한 영역만 복구한 뒤 전체 결과를 `report.csv`로 저장한다.
설계 근거는 [ADR 0001](../adr/0001-resync-recovery.md) 참조.

## 인터페이스

| 이름 | 설명 | 타입 | 기본값 |
|------|------|------|--------|
| `input` | 입력 디렉토리 (`output/jpeg/`) | positional | — |
| `-o, --output` | 출력 디렉토리 | str | `<input>_recovered` |
| `-q, --quality` | 복구본 JPEG 품질 | int | `95` |
| `-j, --jobs` | 병렬 프로세스 수 (`0`=CPU 수, `1`=순차) | int | `0` |
| `--fast` | 빠른 모드(부분 복구 감수); 미지정 시 철저 | flag | 철저 |
| `--time-budget` | 파일당 시간 상한(초, `0`=무제한) | float | 철저 90 / fast 20 |

**철저↔속도 조절**: `_resync_skip`의 탐색 범위로 복구율과 속도가 갈린다. 철저(기본)는
`resync_near=300000` + 전체 스트림 거친 스캔(`full=True`)으로 먼 구멍까지 건너뛴다(복구율↑, 느림).
`--fast`는 `near=160000` + 전체 스캔 끔(빠름). `time_budget`은 심손상 파일의 비용 폭발을 막는
안전장치다(초과 영역은 회색). 단 추출 파일이 큰 경우(수 MB) 기본 budget으로는 시간이 부족해
복구가 도중에 멈춰 회색이 남을 수 있으므로 `--time-budget 0`(무제한)을 권장한다.
(2026-06-29 무손실 최적화로 처리가 8배가량 빨라졌으나, 병렬 부하에서 무거운 파일이 기본 90초를
넘겨 잘릴 수 있어 무제한 권장은 유효하다 — [ADR 0003](../adr/0003-recover-perf-optimization.md).)

## 출력

```
<output>/
  report.csv              # 파일별 복구 결과 (5종 모두 기록)
  recovered/              # 재인코딩된 복구본 (RECOVERED)
  clean/                  # 손상 없던 원본 복사 (CLEAN)
  failed/                 # 무행동(편집·재동기 0회, hole 종료) 원본 복사 (FAILED)
  skip_undecodable/       # 디코드 실패 원본 복사 (SKIP_UNDECODABLE)
  error/                  # 워커 예외 발생 원본 복사 (ERROR)
```

`main`이 실행 전 다섯 서브폴더를 미리 생성하므로,
해당 분류 파일이 없더라도 폴더는 항상 존재한다.
`report.csv`는 최상위에 위치하며 5종 분류를 모두 기록한다.
FAILED는 회색 위주 재인코딩본이 입력 plain 디코드보다 항상 나쁘므로 **원본 바이트를
보존**한다 — 후속 pass(수락 임계 비례화·헤더 복구)가 같은 파일을 재시도할 수 있다.

`report.csv` 컬럼:

| 컬럼 | 설명 |
|------|------|
| `filename` | 원본 파일명 |
| `action` | `RECOVERED` / `CLEAN` / `FAILED` / `SKIP_UNDECODABLE` / `ERROR` |
| `gray_before` / `gray_after` | 복구 전/후 회색(평탄·무채색) 픽셀 비율 (0.0–1.0) |
| `undec_before` / `undec_after` | 복구 전/후 미복구 회색(RGB≈128 + 평탄) 비율 — 무채색 착시 없는 진짜 복구율([ADR 0004](../adr/0004-resync-dc-reset-recovery.md)). DC=0 리셋의 무채색 콘텐츠를 회색으로 오집계하지 않는다 |
| `undec_delta` | `undec_after − undec_before` (부호 포함). 복구가 지표를 악화시킨 파일을 정렬·필터로 즉시 드러낸다 |
| `worse` | `undec_delta > +0.01`이면 `1`, 아니면 빈 값 — 악화 플래그(악화 66건이 장기 미발견된 재발 방지) |
| `recover_sec` | `recover()` 소요 시간(초). resync 알고리즘 시간만(헤더 디코드·RGB 재인코딩 제외). 손상 지점이 많을수록 커지므로 디버깅·성능 지표로 쓴다 |
| `ops` | 적용한 편집·재동기 총 횟수 |
| `sub` / `del` / `ins` | 바이트 치환 / 삭제 / 삽입 횟수 |
| `resync` | 비트위치 재동기(세그먼트) 횟수 |
| `hole` | 복구 불가로 중단한 횟수 |
| `mcus` | 실제 MCU 총수(`mcus_x×mcus_y`) — 수락 임계 잠금(MCU<450) 분석용 |
| `image_size` | SOF 해상도 (`WxH`) |

실행 종료 시 콘솔에 **층화 요약**을 출력한다: action별 건수, RECOVERED undec 평균(전→후),
악화 건수(action별), MCU 대역별(<120 / 120–449 / 450–899 / ≥900) RECOVERED+FAILED의
undec_after 평균과 >0.15 건수 — 평균에 가려지는 소형·악화 케이스를 실행 직후 드러낸다.

## 파이프라인

1. **JPEG 목록 수집** (`recover.py`) — 입력 디렉토리에서 `*.jpg`를 정렬한다.
2. **복구** (`carver/resync.py::recover_file`) — 파일마다:
   - `carver/jpegdecode.py`로 디코더 구성(3-component baseline만 지원, 아니면 `SKIP_UNDECODABLE`).
   - 전체 디코드로 `gray_before` 측정.
   - `recover()`가 디싱크 지점마다 바이트 오라클(치환/삭제/삽입) → 실패 시 resync-skip을 적용.
   - 복구본을 RGB로 렌더 → JPEG로 재인코딩 저장. `gray_after`·편집 통계 반환.
3. **report.csv 작성** (`recover.py`).

## 복구 원리 (알고리즘)

> 배경 지식(엔트로피 코딩·디싱크가 회색/깨짐을 만드는 이유)은
> [JPEG 엔트로피 코딩과 디싱크 원리](../reference/jpeg-entropy-coding.md) 참조.

### 출발점: 디싱크 지점 = 손상 위치

자작 디코더는 표준 클린 JPEG과 일치함이 검증됐다. 따라서 **이 디코더가 정상 디코딩하다가
어긋나는(디싱크) 지점이 곧 실제 바이트 손상 위치**다. libjpeg는 오류복원으로 손상을 그럴듯하게 보이게 만들 뿐
정렬을 복원하지 못하지만, 우리는 손상 지점을 정확히 짚어 정렬 자체를 되돌린다.

### 디싱크 탐지: plausibility

`carver/jpegdecode.py`의 디코더는 다음 중 하나라도 발생하면 그 MCU에서 멈추고
그 지점(frontier)의 비트위치·DC예측값을 정확히 보고한다:

| 신호 | 의미 |
|------|------|
| 무효 Huffman 코드 | 비트 정렬이 깨져 테이블에 없는 코드를 만남 |
| 계수 dequant 오버플로 (DC>1400, AC>6000) | 디싱크로 비현실적으로 큰 계수가 나옴 |
| **비트레이트 초과** (MCU당 평균의 4배) | 코드 길이는 유효하나 비트를 비정상적으로 많이 소비 = "그럴듯하지만 어긋난" 디싱크 |

비트레이트 신호가 핵심이다. 잘못된 정렬에서도 우연히 유효한 코드가 한참 이어질 수 있는데,
그런 경우 MCU당 소비 비트가 비정상적으로 커진다. 이를 잡아 가짜 정렬을 걸러낸다.

### 복구 두 갈래

각 디싱크 지점 `m_d`에서:

**1) 바이트 오라클 (`_best_edit`)** — 단일바이트 손상 복구, 정렬 보존(밀림 없음).

`m_d` 부근 바이트를 한 개씩 **치환(256가지)·삭제·삽입**해보고, 각 후보에 대해
"그 직전 안전 지점부터 몇 MCU나 깨끗하게 디코딩되는가(clean run)"를 측정한다.
clean run을 최대화하는 편집을 채택한다. run이 상한(probe 창 W)에 도달하면 즉시 채택(early-exit).
편집 수락 조건은 잔여 MCU(rem)에 비례한다: `run > 무편집 기준 + min(30, rem//4)` 그리고
`run > min(120, max(20, 0.4·rem))` — 소형 이미지·꼬리 구간에서도 수락이 가능하다([ADR 0005](../adr/0005-scaled-accept-threshold.md)).
→ 디스크 비트플립 등 단일바이트 손상이 여기서 원래대로 복원되며, 비트 정렬이 그대로
유지되므로 **이미지 밀림이 생기지 않는다.**

**2) resync-skip (`_resync_skip`)** — 다중바이트 손상·구멍 건너뛰기.

단일바이트로 안 되면(손상 클러스터/섹터 손상), 재개 비트위치를 **넓게 탐색**한다:
가까운 범위(byte 정렬, 8비트 간격)부터 시작해, 못 찾으면 남은 스트림 전체를 거칠게(64비트) 훑어
clean run이 충분히 긴 재개점을 찾는다. 찾으면 그 지점부터를 새 **세그먼트**로 등록한다.
각 재개 후보 위치에서 DC 예측을 **직전값 캐리와 전체 0 리셋 두 후보로 probe해 clean run이 긴 쪽을
채택**한다([ADR 0004](../adr/0004-resync-dc-reset-recovery.md)). 캐리만으로는 Cb/Cr DC가 틀려 재동기
못 하는 hole을 DC=0 리셋이 살린다(단 DC=0은 Cb/Cr 무채색 캐스트를 만든다 — 진짜 복구율엔 무관, 색
보정은 별도 과제).

- **수락 임계 — 잔여 비례 + 데이터-끝 완주**([ADR 0005](../adr/0005-scaled-accept-threshold.md)):
  probe 창은 잔여 MCU로 캡되고(`W = min(900, 총MCU − m_d)`), 최선 후보는
  `run ≥ max(30, 0.35·W)`이면 수락된다. 예외로 probe가 **버퍼 끝에서 멈춘 후보**(남은 데이터
  전체가 이어지는 절단 파일)는 뒤에 가릴 데이터가 없으므로 `run ≥ 30`이면 수락된다.
  30 미만의 run은 진위를 검증할 신호가 없어 수락하지 않는다.
- **masking 거부:** 재개점이 `m_d`와 거의 같은 비트(`|db| < 24`)면, 이는 어긋난 스트림을 제자리에서
  DC만 리셋해 다시 읽는 **가짜 복구**(masking)다. DC=0 리셋 후보를 추가하면서도 이 조건으로 제자리
  masking을 차단한다.
- **구멍은 회색 유지:** 어떤 재개점도 충분히 길게 디코딩되지 않으면(물리적 소실), 그 영역은
  채우지 않고 회색으로 남긴다.

byte 편집은 우선, 안 되면 resync. 둘 다 안 되면 그 지점에서 종료(이후는 회색).

### 세그먼트 모델과 좌→우 처리

복구 상태는 **세그먼트 리스트** `(시작MCU, 시작비트, DC예측)`로 표현된다. 첫 세그먼트는
`(0, 0, [0,0,0])`. resync마다 세그먼트가 하나 추가된다. 렌더 시 각 세그먼트를 순서대로
디코딩해 전체 이미지를 만든다.

**항상 좌→우(작은 MCU→큰 MCU)로 처리**하므로, 바이트 편집·세그먼트 추가는 언제나 현재
frontier *이후*에만 일어난다. 따라서 이미 확정된 앞쪽 세그먼트의 비트위치는 영향받지 않는다.

> **회귀 주의 (반복/중복 버그):** 과거 버그는 디싱크 후 `mcu_bit[frontier]`가 미기록(0)으로
> 남아, resync가 `base_bit=0`을 읽고 **스트림 맨 처음으로 재동기 → 앞부분을 반복 디코딩**해
> 같은 내용이 주기적으로 중복됐다. 디코더가 디싱크 지점에서 **mcu_bit를 기록한 뒤 멈추도록**
> 고쳐 frontier 비트가 항상 유효하게 했다. `tests/test_resync.py`의
> `test_recover_segments_strictly_increasing_bits`가 세그먼트 비트의 단조 증가(=재디코딩 없음)를
> 검증해 이 회귀를 막는다.

### 무엇을 복구하고 무엇을 남기나

- **복구:** 비트 정렬(→ 구조·디테일). 회색·깨짐을 실제 내용으로 되돌린다. 재동기 실패(hole) 지점은 DC=0 리셋으로 살린다([ADR 0004](../adr/0004-resync-dc-reset-recovery.md)).
- **보류(미해결):** 색 캐스트(DC=0 리셋의 무채색 포함), 이미지 밀림. 구조 복원에 집중한다.
- **남김:** 물리적으로 소실된 영역·데이터 소진 구간은 가짜로 채우지 않고 회색으로 둔다.

## 성능 특성

파일당 처리 시간은 손상 지점 수에 비례한다. 무거운 파일(편집·재동기 수십 회)은 `_best_edit`의
편집 후보 탐색과 그에 따른 `decode_probe`(clean run 측정) 호출이 시간을 지배한다. 2026-06-29
무손실 최적화로 **출력은 불변인 채** 단일 프로세스 6.6배·실전(`-j 12`) 8.2배 가속됐다(삽입 후보
평가의 배열 전체복사 제거 + magnitude 비트 일괄추출). 상세·근거는
[ADR 0003](../adr/0003-recover-perf-optimization.md)·[보고서](../reports/2026-06-29-recover-speedup.md).

`time_budget`은 wall-time 기준이므로 **처리 속도가 결과에 영향을 준다** — 같은 budget이라도 빠른
코드가 더 많이 복구한다. 따라서 변경 전후 출력 동일성(무손실)을 검증할 때는 `--time-budget 0`으로
비교해야 한다(budget이 걸리면 속도 차이가 복구량 차이로 나타나 비교가 성립하지 않는다).

| 손상 없음(편집 0회 & 회색 < 2%) | `CLEAN` | `clean/` — 원본 바이트 복사 |
| 무행동(편집·재동기 0회 & hole ≥ 1 & 회색 ≥ 2%) — 수락 임계 잠금·데이터 소실 등 | `FAILED` | `failed/` — 원본 바이트 복사(회색 재인코딩본을 저장하지 않음) |
| 디싱크 지점을 바이트 편집/재동기로 복원 | `RECOVERED` | `recovered/` — 재인코딩된 복구본 |
| 워커 프로세스에서 예외 발생 | `ERROR` | `error/` — 원본 바이트 복사 |
| 물리적으로 소실된 영역(재동기 지점 없음) | 해당 영역은 회색으로 남김(가짜 채움 금지), 나머지는 복구 | — |
| 입력 디렉토리 없음 | 오류 출력 후 exit code 1 | — |

분류 판정 순서는 SKIP → CLEAN → FAILED → RECOVERED다. CLEAN이 FAILED보다 먼저이므로
"편집 0회·회색 < 2%"는 hole 여부와 무관하게 CLEAN이다. FAILED의 `undec_after` 등 지표는
**저장하지 않은 렌더**(plausibility 정지 렌더)에서 측정한 값이다 — 저장물은 원본 바이트.

## 미해결(별도 과제)

색 캐스트, 이미지 밀림은 복구 대상이 아니다. resync 엔진은 **구조 복원과 회색 제거**에 집중한다.

- **DC 캐리 재동기 실패**는 DC=0 리셋으로 해결했다([ADR 0004](../adr/0004-resync-dc-reset-recovery.md)). 단 DC=0은 재동기 세그먼트에 무채색 색 캐스트를 만든다(진짜 복구율엔 무관, `undec_after`로 확인). **색 캐스트 보정**(인접 세그먼트 DC 추정, 공간 연속성)은 별도 과제다.
- **비트 과소비/데이터 소진**으로 남는 회색은 **데이터 한계**다. 누적 평균 rate([resync-limit](../investigations/2026-06-29-resync-limit.md))도 국소 skew([skew 조사](../investigations/2026-07-01-resync-skew-underconsumption.md))도 재동기로 복구하지 못한다(3차 확인) — 재동기 위치는 clean run으로 채점해야 하며 데이터 소비(skew)는 품질 기준이 못 된다.

2026-07-02 발견 세션에서 확인된 **현행 동작의 추가 한계** (원인·실증은 [사각지대 조사](../investigations/2026-07-02-recovery-tool-blindspots.md)·[blocky·밀림 조사](../investigations/2026-07-02-blocky-shift-dc-offset.md), 후속 계획은 [백로그 W1~W6](../backlog.md)):

- ~~**수락 임계 잠금**~~ — **해소(2026-07-03, [ADR 0005](../adr/0005-scaled-accept-threshold.md))**: 수락 임계가 잔여 비례(`max(30, 0.35W)`)+데이터-끝 완주 규칙으로 바뀌어 소형·연속 손상 간격<450 파일도 재동기가 수락된다(전수 FAILED 66→15, 파일별 회귀 0). 잔여 FAILED는 대부분 헤더 손상·초소형(백로그 W3)과 절단·데이터 한계다. 단 **run<30 꼬리는 여전히 수락 불가**(진위 검증 신호 부재)로 회색으로 남는다.
- **헤더 손상 미복구** — 엔진은 엔트로피 스트림(`dec.buf`)만 편집하므로 DHT/SOF/SOS 등 헤더 손상은 복구 범위 밖이다(SKIP_UNDECODABLE의 실제 주원인). `Decoder`의 빈 huff 미검증 버그는 해결됐다(2026-07-02 — 컴포넌트가 참조하는 테이블 부재 시 거부 → SKIP으로 정분류).
- **재동기 세그먼트의 밀림·색 캐스트** — 재개 비트의 실제 MCU 인덱스(건너뛴 hole의 MCU 수)를 알 수 없어 세그먼트마다 수평 오프셋이 누적되고, DC=0 리셋으로 세그먼트별 색 캐스트가 생긴다(복원 콘텐츠의 육안 지배 결함).
- **온전성 판별의 한계** — "무효 코드 없이 디코드됨"은 스트림 온전성의 증거가 아니다(조밀 코드 공간·DC 물리 범위 — [레퍼런스 §디싱크 판별의 불변량](../reference/jpeg-entropy-coding.md)). clean run 채점은 저엔트로피 구간에서 정렬 판별력이 없다. **DC 물리 범위 불변량도 재동기 후보의 수락/기각 필터로는 쓸 수 없다** — 복구 출력·probe 창이 리셋 오프셋·잔존 드리프트로 불변량을 일상적으로 위반한다(실증·재도입 금지 제약: [ADR 0005](../adr/0005-scaled-accept-threshold.md)).
