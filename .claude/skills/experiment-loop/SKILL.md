# 실험 루프 — 정답 원본이 없는 복구·개선 작업

**목적:** 정답 원본(원래 정상 이미지)이 없으므로 어느 방법이 맞는지 한 번에 알 수 없다. 고정 샘플에서
가설을 하나씩 세워 실험으로 검증하고, 틀린 것을 제거하고, 살아남은 방법만 전체에 적용한다. 아래 규칙은
**검증 없이 성공으로 단정하는 것을 막는다** — 건너뛰지 않는다.

**쓸 때:** 헤더 복구·색상 복구·이미지 밀림(디싱크)·복구율 개선 등 정답 원본이 없어 샘플 실험으로 방법을
찾는 작업. **안 쓸 때:** 동작이 이미 명세로 정해진 기능 구현.

## 메인 플로우

순서를 지킨다. 각 단계의 규칙은 그 단계에서 한 번만 설명한다. 단계를 가로지르는 규칙(문서화·budget·
off-target·통신)은 아래 **"상시 규칙"**에 모아 두었다.

### 1단계 — 문제 정리 + 성공 기준
목표가 틀어지면 이후 전부가 틀린 목표를 향한다. 이 단계에서만은 사용자와 통신을 많이 한다.
1. 사용자 요구를 **내 말로 되돌린다**("즉 X가 손상돼 Y가 안 되는 걸 Z 기준으로 고치는 게 맞나?"). 모호하면
   추측하지 말고 질문한다.
2. **성공 기준 A·B·C를 정의해 작업 노트에 적는다**(작업마다 비중이 다르다 — 헤더는 A, 밀림은 B, 색상은 C 중심):
   - **A 필수 통과(자동)** — 회귀 0(이전 정상 이미지를 깨면 실패) + 구조 타당(디코드 성공, 해상도·양자화·크로마
     서브샘플 내부 일관). 정답 없이 가능한 자기일관성 검사. **A를 어기면 B·C가 아무리 좋아도 실패.**
   - **B 진척 지표(반자동)** — 프록시가 옳은 방향인지(회색 % 감소, 디코드 스캔라인·복구 바이트·디코드 이미지 수 증가).
   - **C 육안(수동)** — A·B 통과 후보를 몽타주로 비교. "정답인가"가 아니라 **"베이스라인보다 자연스러운가"**를 묻는다.
3. **셋 중 하나로만 판정하지 않는다**(B는 디코드되는 쓰레기로 속을 수 있고, C는 멈출 때를 못 정하며, A는 진척을 못 잰다).
4. 기준은 잠정 시작해 다듬되 — **조이는 변경은 내가, 느슨하게 푸는 변경은 사용자 승인**(자기기만 방지). 변경은
   조사 기록에 남긴다.

### 2단계 — 샘플 고정 + 베이스라인 저장
샘플이 매번 바뀌면 비교가 안 된다. 브랜치당 한 번 고정한다.
1. 샘플에 **고치려는 실패 케이스 + 회귀 가드(이미 정상인 이미지)**를 함께 넣는다(실패만 넣으면 트레이드오프를
   놓친다). 쉬운 것만 고르지 말고 실패 양상의 다양성을 대표하게 한다(과적합 방지). 사용자가 지정해도 된다.
2. **베이스라인**(이미지별 몽타주 + 지표)을 scratchpad에 파일로 저장한다(대화에만 두면 압축으로 사라진다).
   재생성이 비싼 숫자(예: 변경 전 실전 처리 시간)는 즉시 조사 기록에 전사한다.

### 3단계 — 루프 (자율, 통신 최소)
종료 조건까지 매 사이클 순서대로:
1. **원인 분석** — 깨진 샘플을 직접 열고 probe로 비트·바이트를 본다. **이 단계에선 carver 본체
   (`carve.py`·`recover.py`·`carver/*`)를 수정하지 않는다**(조사용 스크립트만).
2. **가설** — 구체·반증 가능하게("X가 손상돼 Y가 안 된다, Z를 하면 복구된다").
3. **예측을 실험 전에** — 어느 이미지가 어느 방향인지 **이름까지**("#3·#7 회색→복구, 가드 #1·#2 불변"). 결과
   본 뒤 끼워맞춤을 막는다.
4. **실험** — 스크래치 하니스에서 **샘플에만**(여러 방법 빠르게 비교, 본체 안 흔듦). 작고 확신 서면 본체를 수정해
   샘플에만 돌려도 된다.
5. **결과 분석** — 자동 판정(디코드·회색·구조·예측한 방향)과 육안 판정 **모두 내가** 한다. 자동에서 떨어지는
   가설은 묻지 않고 버린다. 단 **새 문제의 첫 그럴듯한 후보 1회만** 사용자에게 보여 기준을 맞추고("이걸 복구됨으로
   판정하는 게 맞나"), 이후 자율. 판정 기록은 지표·결함 패턴으로만(이미지 시각 내용 묘사 금지).
6. **조사 기록** — [write-investigation](../write-investigation/SKILL.md)의 5요소(가설/실험/예측/증거/판단)로 한 항목 추가.

**멈추고 사용자에게 먼저 확인:** 육안으로 확신이 안 설 때 / 방향이 여러 갈래일 때 / 여러 사이클 정체일 때.
**종료:** ⓐ 성공 = A 유지 + B 도달 + C 통과. ⓑ 수렴 = 사이클당 개선폭이 노력 대비 무의미. **완벽 복구가 불가능한
손상은 그대로 둔다** — 데이터 한계에서 멈추는 게 정상이며 없는 완벽을 강요하지 않는다.

### 4단계 — 전체 적용 (세 단계 모두)
샘플에서 검증한 코드와 출하 코드가 다르면 검증이 무의미하다.
1. **이식** — 검증된 방법을 carver 본체에 구현.
2. **샘플 재검증** — 이식한 본체 코드로 샘플을 다시 돌려 스크래치 결과와 일치하는지 확인. 불일치면 전수로 안 넘어간다.
3. **전수 적용** — 일치하면 전체 데이터에.

**전수에서 실패가 나오면** 버그가 아니라 "샘플이 전체를 대표 못 함" 신호다 → 그 케이스를 고정 샘플에 추가하고
3단계로 돌아간다.

### 5단계 — 리파인 패스 (main `--squash` 머지 직전)
루프 중 쌓인 조사 기록·레퍼런스를 결론 문서로 증류한다(백지 작성 아님). 아래를 생성·갱신하고 `review-doc`으로
검토한다(작성은 대응 write-*, 경계는 [doc-roles](../shared/doc-roles.md)):
- 영향받은 **spec** · **architecture.md** · **README.md** · 필요한 **ADR**(결론은 full, 과정은 조사 기록 링크)·
  **보고서** · 루프 중 못 남긴 **조사 기록·레퍼런스**

**머지는 자율로 하지 않는다** — 변경 요약·최종 수치·정리 문서를 제시하고 사용자 검토를 받아 그 의견을 따른다
(수정이면 4·3단계로 되돌아간다).

## 상시 규칙 (단계를 가로지른다)

### [필수] recover는 항상 `--time-budget 0`
베이스라인·실험·전수 예외 없이 무제한(하니스: `recover(time_budget=0)`). budget은 wall-time 기준이라 처리
속도가 바뀌면 복구량이 달라져 베이스라인↔실험 비교가 깨지고, 시간 부족으로 남은 회색이 회귀로 오인돼 **기준
A·B를 거짓으로 떨어뜨린다.** (`carve.py`엔 budget 없음. budget 상한은 루틴 운영의 비용 안전장치일 뿐.)

### [필수] 결론 문서는 루프 중에 쓰지 않는다
ADR·spec·보고서는 리파인에서만 쓴다. 유동 결론을 일찍 굳히면 다음 사이클이 뒤집고, 써 둔 결론이 판단을 묶는다.
결정 지점이 보이면 맥락만 조사 기록에. **문서 타이밍:** 조사 기록=매 사이클 라이브, 레퍼런스=확립 즉시,
ADR·spec·보고서=리파인. 부피 큰 원시 출력(csv·로그·덤프)은 scratchpad 원장에 두고, 보고서·ADR 숫자는 거기서
**그대로 전사**한다(기억·재계산 금지 — 숫자가 틀어진다).

### [필수] off-target 발견은 쫓지 않고 라우팅
곁가지를 바로 추적하면 실험 대상이 오염되고 조사 기록에 무관한 내용이 섞인다. 기록만 즉시 하고 착수는 미룬다
(사용자와 함께 결정).

| 발견 | 적는 곳 |
|------|---------|
| 새 **포맷 사실** | `reference/` (즉시) |
| 목표와 다른 **문제·버그** | `docs/backlog.md` |
| **목표 자체를 다시 잡게 하는** 발견 | 현재 조사 기록 + 승인 후 목표 재설정 |

### 통신 리듬
1단계 많이(목표·기준·샘플 합의) → 3단계 최소(첫 후보 1회 캘리브레이션 + "멈추고 확인" 조건만) → 4단계 직전
1회(검토 후 전수·커밋) → 5단계 후 머지 직전 1회(검토받고 따른다).

## 자가점검

- [ ] 성공 기준 A·B·C를 적고, 샘플에 회귀 가드를 넣고, 베이스라인을 저장했나?
- [ ] 매 사이클 예측을 **실험 전에** 이름까지 적었나? recover를 예외 없이 `--time-budget 0`으로 돌렸나?
- [ ] 전체 적용에서 이식 → 샘플 재검증 → 전수 3단계를 모두 거쳤나?
- [ ] 루프 중 결론 문서를 안 쓰고 off-target을 라우팅했나? 머지 전 사용자 검토를 받았나?
